# Architecture Decision Records

Use ADRs for decisions that are worth remembering and defending in an interview or design review.

Each ADR should capture:
- Context
- Decision
- Alternatives considered
- Trade-offs
- Failure/security implications
- What evidence would make us revisit the decision

Early expected ADRs include:
- custom minimal Agent loop before adopting an orchestration framework;
- sandbox interface and eventual microVM/runtime selection;
- state/checkpoint persistence;
- tool contract and idempotency semantics;
- model/provider abstraction.
