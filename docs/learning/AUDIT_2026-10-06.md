## 4. 对当前能力的谨慎判定

**直接证据：** 学习者能说出 QK^T、scaling、Softmax、weighted V 主流程；能独立推导一个 1×3 到 1×2 的矩阵 shape；对“为什么参数可训练”提出了有效追问。

**提示后理解：** Projection 与 Concat/W_O 的基本描述，多头各自参数与不同关注模式的关系。

**尚未证明：** 一般矩阵投影与信息损失边界、完整 MHA 独立实现、导数/链式法则、训练循环、完整 Transformer 与 Agent 的独立系统答辩。

因此不能把 Day 5 标为完成，也不能反过来否定前面已经发生的学习。进度以具体能力证据迁移到新模块，不按“讲过几天”计算完成度。

## 5. 教学中需要纠正或复核的表述

这些是后续教学质量检查项，不是要求学习者今天重新考试。

- “不加位置编码，ABC 与 CBA 完全一样”需要讲清无位置/顺序信号且不引入改变该性质的 mask 时的置换关系，不能把输出随输入重排说成所有数值原位不变；causal mask 另有顺序约束。
- “投影不是取一部分，所以不丢信息”并不成立；普通降维不能保证保留任意输入全部信息。
- “同样都是 512 维所以视角一样”混淆了维度大小和具体计算参数；降低到 64 维主要是设计/资源权衡，不是产生不同视角的唯一必要条件。
- 独立 Head 可以形成不同关注模式，但不保证各有稳定、互斥、可命名的语义职责。
- 不应把一般卷积核尺寸当作确定的压缩倍数，也不应靠“不要再想卷积”代替对操作本身的说明；具体等价和边界在有必要时用公式核对。
- “反向传播算每个参数对错误的贡献”只能是粗略类比，应落实到局部敏感度；不是因果责任分配，也不是所有参数每步必然非零更新。

## 6. 新方案采取的结构性修复

1. 从每天一个术语，改为有明确硬依赖/推荐顺序的能力模块。
2. 用 M02 完整训练机制填补共同基础，而不是在 W_O 问题后临时插课。
3. 用 P1 微型 Transformer、P2 可评测 RAG、P3 可靠 Agent 把概念落地。
4. 保留强项的加速通道；未验证知识不按背景猜测。
5. 区分独立通过与延迟通过；评分必须有证据。
6. GitHub 维护当前可写计划与状态，Project Sources 保留偏好/规则及带日期快照；上传文件不能假装已经自动改好。
7. 每单元开课前主动检查前置、练习和验收，而不是靠学生提问找遗漏。

## 7. 本次修订的完成边界

交付是课程设计与工作流修复，不是声称已经完成未来 80–106 小时教学，也不是已经写出和运行三个项目。

保留旧 PLAN 的不可变 Git 历史入口，以及现有 Day 1、BASELINE、架构、面试与 ADR 原文。后续每日讲义和代码按统一模板逐单元建立，未产生的产物必须标为待实现。
