# 学习日 L054–L072：平台、安全、评估与综合验收

版本：2026-10-06。所属总纲：M07–M10。索引 ../DAILY_PLAN_V2.md。以下是提前准备的学习任务，不是当前已经完成的项目或测试结果。

## 统一执行与范围

先核验前置证据、到期复习和实际工具版本。每课按动机→机制→可验证练习→独立说明→边界追问执行，分别记录 Concept、Mechanism、Engineering、Interview。失败仅回补依赖；成功后安排延迟验证，不用项目复杂度或讲述流畅代替掌握证据。

实践延续 P2/P3，默认隔离测试、fake provider、mock 写操作。没有授权不接真实账号或生产系统；没有确认不购买服务、不运行付费训练。安全采用防御测试，不把少量测试通过写成绝对安全。

## M07｜MCP、Harness 与 Sandbox

### L054｜MCP 的协议边界
**前置：** L046–L047、L053。
**问题与目标：** 区分工具协议、模型能力、执行 runtime 与沙箱隔离。
**教学顺序：** host/client/server→tools/resources/prompts→消息与生命周期→能力协商→模型发出工具意图与协议请求/真实执行的不同层次。
**练习与产物：** 把已有只读工具映射成 MCP 接口，画一次完整请求的参与方；固定规范与 SDK 版本，核对请求、响应和错误消息。优先使用维护中的 SDK，不要求手写整个协议栈。
**独立验收：** 说明 MCP 标准化了什么、没有替代哪些授权/恢复/隔离责任；不用“远程命令执行”概括全部协议。
**错误与回补：** 不把连接上 server 当成功完成业务。工具契约不清回 L047；下一课处理 transport 和身份。

### L055｜MCP Transport、身份与授权
**前置：** L054、已有后端认证基础。
**问题与目标：** 明确谁代表谁访问什么资源，协议互通不自动等于用户同意。
**教学顺序：** 本地与远程连接方式→身份主体/凭证→授权范围与目标服务→请求取消/超时→连接重建；具体流程必须按选定规范版本核对。
**练习与产物：** 在受控 server 测试未授权连接、作用域不足、凭证过期和请求取消；画出用户、host、client、server、业务服务之间的信任边界，秘密不进入模型上下文与公开日志。
**独立验收：** 解释工具发现和业务数据读取为什么可能需要不同权限；指出 confused deputy 风险的责任边界。
**错误与回补：** 不能用模型传入的身份替代可信会话身份。版本/SDK 差异先查官方来源，不凭旧教程推断。

### L056｜Harness：围绕模型的执行支撑层
**前置：** L041–L042、L049–L055。
**问题与目标：** 让“Agent 平台”的组件边界可解释、可替换。
**教学顺序：** 本项目将 Harness 定义为工具装配、context 管理、执行/恢复、预算、权限与评估支撑层；比较 model、protocol、SDK、runtime、sandbox、gateway 的职责。术语不是所有项目的统一标准。
**练习与产物：** 对 P3 画职责与调用边界，列输入/输出/状态/失败归属；替换 fake model 或工具适配器而不改变任务语义；写一份组件边界 ADR。
**独立验收：** 给“模型返回错误参数”与“执行器重复提交”两种故障，指出各层应采取的动作。
**错误与回补：** 不把所有模块塞进 Harness 这个词而不说明接口。边界含混返回具体 loop/状态日。

### L057｜Sandbox、容器与 MicroVM 的威胁模型
**前置：** L047–L049、L051、L056。
**问题与目标：** 从不可信代码可能做什么推导隔离，不从“用了容器”直接推导安全。
**教学顺序：** 资产/威胁→进程/文件/网络→CPU/内存/时间/磁盘限制→凭证注入→生命周期/清理→容器与 microVM 的隔离和运维取舍。
**练习与产物：** 为受限教学任务制定策略，验证越目录读取、禁止外联、超资源和残留文件处理。设备不支持真实隔离时只验收设计与 mock lifecycle，实际隔离能力标待验证。
**独立验收：** 解释 sandbox 没有替代的应用授权与数据访问策略；给出选择更轻或更强隔离的条件。
**错误与回补：** 不要求本轮自建虚拟化平台，不把 mock 拒绝当内核隔离证据。权限问题回 L051/L055。

### L058｜MCP × Runtime × Sandbox 集成门槛
**前置：** L054–L057、L053。
**问题与目标：** 验证跨边界组合后的行为，而不只验证组件各自可用。
**练习与产物：** 追踪请求身份→工具契约→策略→受控执行→artifact→结果→清理；注入取消、超时、server 断开和重复响应，检查资源释放及状态一致性；输出版本清单与证据矩阵。
**独立验收：** 说明故障由哪层感知、谁负责停止与恢复；证明受控测试中的越权被拒、残留被处理，未实测能力明确标注。
**错误与回补：** 协议响应成功不等于任务目标完成。按边界回 L054–057，不一概归因于模型。
**下一阶段：** 进入系统评估与发布质量；之前的最小评估/权限测试继续保留。

## M08｜Evaluation、可靠性与企业架构

### L059｜Evaluation 的对象、指标与不确定性
**前置：** L018、L035、L044、L053；本章深化已有评估。
**问题与目标：** 区分测试、观测和质量评估，避免用单次成功率替代稳定能力。
**教学顺序：** task/case/trial→输入与最终环境状态→outcome/trajectory→指标定义→重复试验→样本量与区间直觉；准确率、成本、延迟、拒答等各有适用对象。
**练习与产物：** 统一 P2/P3 的评估 schema，按题型分组；为同一任务做重复试验，报告样本数、估计值与不确定性，不只报一个小数。
**独立验收：** 说明 9/10 成功与 900/1000 成功不能被简单当作同样强的证据；区分能力波动与运行错误。
**错误与回补：** 不预设所有指标越高越好。概率/统计缺口回 L003 与小样本试算，必要时拆分本日。

### L060｜Grader、人工校准与评估泄漏
**前置：** L059。
**问题与目标：** 判断评分器是否真的在评估目标，而不是让另一个模型随意打分。
**教学顺序：** code/model/human grader→rubric→标注分歧→人工校准→judge 偏差→test set 污染→保留集；可确定校验优先代码，语义评分保留人工抽查。
**练习与产物：** 对同一批输出进行盲评/规则评分，整理分歧；测试冗长但错误、有引用但无支持等反例；固定 rubric 版本和保留题。
**独立验收：** 解释为什么强模型当 judge 仍需校准；如何区分 grader 改进与被评系统改进。
**错误与回补：** 不把评估题发给待测系统调参后仍称它独立测试。数据划分问题回 L018/L035。

### L061｜Trace、指标、SLO 与故障定位
**前置：** L031、L049、L053、L059。
**问题与目标：** 让观测服务于判断哪里坏了，并避免把日志齐全当质量合格。
**教学顺序：** trace/span→task/tool/model/retrieval 关联→错误分类→TTFT/步骤时延/尾延迟→服务目标→预算与告警；日志裁剪、脱敏与身份隔离同时处理。
**练习与产物：** 给 P3 加结构化事件与跨组件关联 ID；注入慢模型、慢检索、工具失败，凭观测定位；保存指标定义和诊断路径。
**独立验收：** 区分“系统没有报错”和“任务完成正确”；说明某个时延指标不能独自代表体验。
**错误与回补：** 不把 prompt/secret 全量记录当可观测性最佳实践。身份隔离在下一日系统检查。

### L062｜多租户、IAM 与全链数据隔离
**前置：** L038、L042、L047、L055、L061。
**问题与目标：** 从请求到索引、cache、memory、checkpoint、artifact、日志都保留正确权限语境。
**教学顺序：** 可信 tenant/principal→资源策略→传播与服务边界→缓存键/索引过滤→任务恢复身份→密钥与审计→删除/保留策略。合规相关决定另需相应专业核验，本课不提供法律结论。
**练习与产物：** 构造同名文档/同问句的两个租户，测试检索、缓存、记忆、恢复任务和日志越权；检查租户字段丢失的负例，形成数据流威胁模型。
**独立验收：** 解释“每张表有 tenant_id”为何不够；指出至少一处可能被忽略的派生数据泄漏路径。
**错误与回补：** 不把客户端传 tenant_id 当服务端身份认证。失败回对应存储/协议层。

### L063｜Model Gateway、成本、降级与发布
**前置：** L029–L034、L048、L050、L061–L062。
**问题与目标：** 模型服务异常或费用增长时，系统怎样可控地运行和回退。
**教学顺序：** provider adapter→模型能力/版本→限流与并发→timeout/retry→routing/fallback→token/费用预算→灰度/回滚；fallback 要兼容工具和输出契约，不只“换个模型名”。
**练习与产物：** 用 fake provider 模拟 429、超时、结构不兼容、部分流输出和价格配置变化；验证预算不会因重试失控；写模型版本与配置回滚方案。
**独立验收：** 解释为什么自动 fallback 也可能降低质量或造成重复动作；区分系统可靠性和模型质量门槛。
**错误与回补：** 不依据旧价格表填当前费用。实际测量写明版本/日期；外部副作用边界回 L048。

### L064｜发布门槛：回归、权限与运行风险
**前置：** L058–L063。
**问题与目标：** 将评估变为发布决策，而不是课后装饰性报告。
**教学顺序：** 单元/契约/集成/语义回归→安全与副作用门槛→质量/成本/延迟基线→变更范围→灰度→停止/回滚；确定性安全约束与有噪声质量指标分开。
**练习与产物：** 为改 prompt、改模型、改检索器各定义必跑测试；做一次故意退化版本并验证被门槛拦住；提交可重复评估命令、配置与一份发布判定。
**独立验收：** 给一个质量升但越权失败的版本，解释为何不能简单按总分发布；明确测试不能证明所有未知攻击都安全。
**错误与回补：** 数据或 grader 改动不可藏在同一比较里。证据不足回 L059–060；下一章整合成一件可交付工程作品。

## M09｜综合项目与架构答辩

### L065｜把能力映射到一份明确需求
**前置：** P2/P3 阶段门槛与 L064；前期产物可复用。
**问题与目标：** 综合项目不是堆满所有名词，而是满足一个具体企业文档问答和受控任务执行需求。
**教学顺序：** 使用者/任务→数据与权限→成功和非目标→负载/成本假设→信任边界→可交付范围；未知项目事实写假设，不补造真实生产数据。
**练习与产物：** 写一页需求与验收合同，选定一个只读流程和一个 mock 写流程；注明限制、风险和本轮不做事项，冻结用于最终验收的任务集。
**独立验收：** 说明为何不需要另一层 Agent 或图索引；有需求变化时哪些模块受影响。
**错误与回补：** 不以“企业级”替代负载和风险定义。需求不清先修本日，不开始全面重构。

### L066｜贯通一条可运行的垂直流程
**前置：** L065、P2/P3 已有最小实现。
**问题与目标：** 使用户请求、检索、决策、工具、状态与最终结果真正闭合。
**教学顺序：** 入口与身份→任务状态→检索证据→模型/工具→批准/执行→引用和结果→观测；优先一条端到端可验证路径，不同时增加功能。
**练习与产物：** 整合 P2/P3/MCP 适配，跑正常、无答案、越权与取消四条路径；记录实际环境结果。P1 用作机制学习证据，不强迫用 tiny LM 充当有质量的企业基础模型。
**独立验收：** 根据 trace 解释每步为何存在；指出哪部分是已测试、哪部分依赖真实 provider 尚待验证。
**错误与回补：** 局部 demo 相加不代表系统集成完成。根据失败层回相应章节。

### L067｜基准、容量与单变量优化
**前置：** L031–L034、L059–L066。
**问题与目标：** 在可重复条件下判断改动是否值得。
**教学顺序：** 固定数据/模型/配置→测量工作负载→成功率/成本/分位延迟→识别瓶颈→一次一个改动→保留失败案例；课堂小规模测量不能外推成生产容量承诺。
**练习与产物：** 选择 context 裁剪、缓存、检索策略或并发控制中的一项优化；前后对照，报告样本量、环境与质量变化，写是否采用的 ADR。
**独立验收：** 说明为什么性能更快但证据缺失更多可能不值得；定义追加测试条件。
**错误与回补：** 不同时更换模型和检索后只给单一提升数字。实验设计问题回 L059–060。

### L068｜框架对照：保留机制，不追 API 清单
**前置：** L046–L053、L056、L066。
**问题与目标：** 用已理解的 runtime 作为参照，判断编排框架的真实收益和隐藏成本。
**教学顺序：** 列当前重复工作→核验候选框架维护/版本→仅迁移一条流程→状态/恢复/工具/观测语义对照→供应商锁定与升级风险。只选一个框架，不同时学三套。
**练习与产物：** 在相同测试上比较自写最小 loop 与候选实现；记录代码/配置差异、恢复语义和失败可诊断性。选择时查官方资料，不按旧热度榜预定。
**独立验收：** 给出保留自写或采用框架的条件；解释框架未替代的安全和评估职责。
**错误与回补：** 不以代码行更少直接推出可靠性更高。未能解释抽象返回 L056。

### L069｜故障演练、删除、恢复与 Runbook
**前置：** L049、L058、L062–L068。
**问题与目标：** 从“能运行”走到“知道坏了怎么办、如何停止与恢复”。
**教学顺序：** 故障分级→诊断/止损→任务取消/重试策略→checkpoint/数据恢复→版本回滚→删除与保留检查→审计复盘。
**练习与产物：** 演练 provider 不可用、索引版本不匹配、进程中断和租户数据删除中的至少两项；记录检测、恢复步骤、实际结果与未覆盖风险，完善 runbook。
**独立验收：** 说明谁有权做恢复，怎样避免恢复后重复副作用或重新出现已删除数据。
**错误与回补：** 文档里的恢复步骤必须与演练证据一致，不能只写“重启服务”。状态/权限问题回对应章节。

### L070｜综合作品交付与工程门槛
**前置：** L065–L069。
**问题与目标：** 交付别人可以理解、运行和质疑的工程作品。
**练习与产物：** 汇总运行入口、版本锁定、样例配置、数据许可说明、测试与评估命令、报告、架构/信任边界、至少三份 ADR、runbook、已知限制；从干净环境复跑关键流程。
**独立验收：** 接受一个需求变化、一项越权诱导和一次中断；用证据解释设计和取舍，未测部分明确列为限制。
**错误与回补：** 不把完成所有文档当所有能力通过；代码、结果、独立说明分别核查。项目不能复现先修入口/环境，不写“已交付”。
**下一阶段：** 进入无提示综合表达和延迟验证；M10 已贯穿前面每个模块，不是到这才开始面试练习。

## M10｜独立表达、延迟复测与后续路线

### L071｜机制答辩：Transformer、RAG 与 Agent
**前置：** 各核心模块已有独立通过证据；预先检查间隔复习队列。
**问题与目标：** 脱离老师刚给的答案，独立解释与迁移。
**执行方式：** 一次一个问题，先完整回答再追问，不提前给答案模板。分别覆盖从输入到联合训练、检索错误诊断、工具/状态/副作用链；根据答案选新配置或反例。
**产物与验收：** 保存原始回答摘要、提示次数、技术错误与四维评价；能解释机制、完成新例并处理边界才独立通过。当天流畅复述不能代替延迟回测。
**错误与回补：** 表达不足只练结构；机制错误回对应学习日；未见代码证据不补写 Engineering 高分。

### L072｜系统设计、Re-baseline 与下一阶段
**前置：** L070–L071；读取原 BASELINE 和各阶段真实证据。
**问题与目标：** 比较学习前后具体能力，而不是以天数证明成长。
**执行方式：** 给一个新企业任务，从需求、数据、模型、检索、Agent、权限、成本、评估到运维完整设计；一次一个追问，加入约束变化，要求解释舍弃了什么。
**产物与验收：** 输出有证据的 re-baseline、薄弱点优先级与后续计划；分别标机制、实现、选型、表达和延迟保持情况，不宣布“已精通整个 AI”。
**延伸路线：** 岗位需要时另立多模态/语音实时 Agent、进阶统计实验、深度微调与偏好优化、分布式训练、GPU 系统等完整模块。它们不以“今天顺便讲一点”替代完整教学；本轮只建立选型边界。
**最终边界：** 72 个学习日是准备好的路径，不是学习速度或岗位晋级保证；未通过门槛就增加回补与实践，不删核心知识凑日历。
