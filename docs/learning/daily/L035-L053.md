# 学习日 L035–L053：RAG、Context、Memory 与 Agent

版本：2026-10-06。所属总纲：M05–M06。索引 ../DAILY_PLAN_V2.md。本文件预备每日目标、机制、练习和验收；所有实验产物尚待学习时实际实现。

## 共同执行规则与项目线

每卡先核对前置、真实工程证据和到期复习，再做动机→机制→最小实现→无提示解释→边界追问。不能因用户做过平台就直接免测，也不从零重复后端基础。Concept、Mechanism、Engineering、Interview 分开记录；失败返回指定依赖，实际报告与计划分离。

P2 是可评测阅读问答系统；P3 复用 P2 作为检索工具，不另造一套索引。未提供真实项目源码前不声称完成对其审计。默认使用小型合成或授权语料、两个测试租户、可重复的 fake provider 和 mock 写工具。fake 只验证流程，不能证明真实检索 embedding 或 LLM 质量。

从 L035 定义评估集和权限约束，从首次工具执行开始验证授权、预算和副作用；M08 是深化，不是首次做评估。语义质量门槛根据任务风险在调参前登记，不设一个脱离业务的统一高分目标。

## M05｜RAG、Context 与 Memory

### L035｜RAG 目标、证据与评估基线
**前置：** L005、L018、L029；已有检索经验作为诊断背景。
**问题与目标：** 明确哪些问题缺知识、哪些缺推理或流程，避免把所有失败都归为检索不够。
**教学顺序：** 用户问题→可访问语料→候选证据→模型回答→出处与拒答；同时建立无检索与最简单检索基线。
**练习与产物：** 建立包含直接问答、跨段、多跳、无答案、歧义和越权的教学问题集；每题记录证据位置、预期行为、租户与划分。可先取 30 题作为启动规模，明确这不是统计充分性的保证。
**独立验收：** 说明“答案碰巧对”为什么不等于 RAG 证据链正确；区分开发题与最终保留题。
**错误与回补：** 不先调 prompt 再事后挑好例做测试集。目标模糊回任务定义；下一课保证证据可被正确解析。

### L036｜Parsing、Chunking 与来源追踪
**前置：** L035。
**问题与目标：** 文档结构和信息边界怎样影响后续检索与引用。
**教学顺序：** 文档→标题/段落/表格→chunk→metadata/source offsets；对照固定长度、结构切分与 overlap。图片/PDF 表格需要保留结构与来源，不能把文本抽取成功当语义完整。
**练习与产物：** 对同一小语料做两种切分；记录跨段指代、表格行列、重复内容的失败样例；每个 chunk 保留 document ID、版本、位置和权限标记。
**独立验收：** 给一个边界错误解释如何导致无证据或错误引用；提出 chunk 方案的验证方法而非固定“最佳长度”。
**错误与回补：** chunk 越小不必然更准，overlap 越大不必然更好。解析质量不足先修解析；下一课做 dense retrieval。

### L037｜Retrieval Embedding 与相似度
**前置：** L002、L005、L035–L036。
**问题与目标：** 解释检索向量、匹配分数与语言模型内部 token 表示的差别。
**教学顺序：** query/document 编码→向量空间→点积/余弦/距离→归一化与模型训练任务→近义/同词异义失败；维度相同不代表两个 embedding 模型空间兼容。
**练习与产物：** 先用可检查小向量实现精确 Top-K，再接一个实际可用且版本固定的 embedding 模型；保存输入前缀、归一化、维度与结果。无模型资源时只验收计算，不预写语义质量通过。
**独立验收：** 解释为什么不能把模型 A 的 query 向量直接搜索模型 B 的旧索引；区分相似与证据充分。
**错误与回补：** 不把高相似度当正确概率。数值混淆回 L003；下一课处理索引与更新。

### L038｜向量索引、ANN 与数据生命周期
**前置：** L036–L037；后端存储基础。
**问题与目标：** 让检索服务能更新、删除和按身份过滤，而不只展示一次查询。
**教学顺序：** 精确搜索基线→ANN 的召回/延迟取舍→metadata/ACL 过滤→document/chunk/index 版本→幂等 upsert、删除、重建与 embedding 迁移。
**练习与产物：** 以精确结果对照 ANN；建立两租户样例，测试修改、删除和索引重建；记录哪些过滤发生在何处，权限检查不依赖模型自觉。
**独立验收：** 解释为何后置过滤可能影响有效候选数量；给出删除如何覆盖索引、缓存和派生数据的方案。
**错误与回补：** 同维度 embedding 升级不能默认原索引可用。身份/版本不明确先修数据模型；下一课加入稀疏检索。

### L039｜Sparse、Dense 与 Hybrid 检索
**前置：** L035、L037–L038。
**问题与目标：** 精确编号/术语与语义改写需要怎样的不同匹配方式。
**教学顺序：** 倒排/BM25 的关键词直觉→dense 的语义匹配→候选合并→排序融合；不直接相加量纲不同的原始分数而不说明处理方法。
**练习与产物：** 对产品编码、专有名词、同义改写三类题做 sparse/dense/hybrid 对照；记录 Recall@K、候选数量、延迟和失败案例；一次只改检索策略。
**独立验收：** 说明 hybrid 何时值得额外复杂度，何时未必改进；解释未入候选的证据后续无法凭 reranker 找回。
**错误与回补：** 不只挑 hybrid 获胜样例。指标/题集问题回 L035；下一课提升候选排序与查询表达。

### L040｜Reranking、Query Rewrite 与分层诊断
**前置：** L039。
**问题与目标：** 区分召回、排序和生成的问题，避免同时修改整个 pipeline。
**教学顺序：** Recall@K 与排名质量→reranker 输入/成本→query rewrite/多查询→候选去重→分层对照；改写不能擅自改变用户约束。
**练习与产物：** 在同一候选集合上比较有/无 reranking；另做 query rewrite 对照；记录召回不足和候选排序不佳的不同案例，核对多查询成本。
**独立验收：** 解释“检索不到正确段落但 reranker 很强”为什么仍失败；提出先测哪个阶段。
**错误与回补：** Top-K 增大可能增加噪声与成本。标签不足回 L035，候选质量不足回 L036–039；下一课组装 context。

### L041｜Context Construction 与证据引用
**前置：** L029、L036、L040。
**问题与目标：** 把找来的段落变为有预算、可追溯且不把数据当指令的上下文。
**教学顺序：** 排序/去重→token 预算→证据边界与来源标签→必要压缩→生成→引用核对/拒答；context window 大不等于应塞入所有材料。
**练习与产物：** 在固定输入预算下比较原文与压缩方案；加入冲突证据、过期证据、文档中的恶意指令；检查引用是否支持对应结论及能否追溯原文。
**独立验收：** 区分“答案带链接”和“引用真的支持答案”；说明无法获得足够证据时系统怎样回应。
**错误与回补：** 格式隔离只是措施之一，不能保证 prompt injection 被消除。证据链错误回 L036；下一课处理长期状态。

### L042｜Memory 不只是向量库
**前置：** L041；已有状态管理经验。
**问题与目标：** 区分当前 context、任务状态、长期记忆、缓存和模型参数。
**教学顺序：** 写入条件→结构化/语义记忆→检索与作用域→冲突/置信与来源→时效/TTL→纠正与删除→使用记录；session 与 tenant 边界明确。
**练习与产物：** 设计偏好记忆和任务状态的不同 schema；测试新旧偏好冲突、错误记忆纠正、跨会话召回与跨租户拒绝；保存生命周期表。
**独立验收：** 解释“历史全部存向量库”为何不足以解决 memory；说明记忆删除与对模型权重训练是不同操作。
**错误与回补：** 不自动保存敏感信息，不把模型总结视为原始事实。状态边界混淆回系统数据模型；下一课比较图检索。

### L043｜GraphRAG / LightRAG：从问题决定复杂度
**前置：** L035–L041。
**问题与目标：** 联系阅读系统经验，判断实体关系结构在什么任务上产生可验证收益。
**教学顺序：** 简单向量 RAG 基线→实体/关系与出处→局部关系、多跳路径和全局问题→抽取错误与维护成本→与原文证据共同使用。具体 LightRAG 实现按实际版本核对，不将所有 GraphRAG 当同一种算法。
**练习与产物：** 对一小段有授权文本建立带出处的实体关系样例；选直接问答与跨段关系题做对照；记录抽取错误如何传播到答案以及回到原文的路径。
**独立验收：** 提供一个值得上图、一个不值得上图的场景及评估依据；不能用“图更高级”作答。
**错误与回补：** 抽出的边不是天然可靠事实。证据不足回 L035/L041；下一课做 P2 总体验收。

### L044｜P2 验收：质量、权限与更新闭环
**前置：** L035–L043。
**问题与目标：** 交付可评测 RAG，而不是只有正常问答 demo。
**练习与产物：** 用保留题比较基线与最终方案；分别报告解析、召回、排序、答案支持度、拒答、成本/延迟；完成文档更新、删除、越权和冲突证据测试；提交 P2 README、配置、题集和报告。
**独立验收：** 拿一个失败案例定位层次并提出单变量实验；无权限材料不得进入未授权用户的生成上下文与可见日志；引用能回溯。
**错误与回补：** 没有真实模型调用时仅标系统正确性部分通过，语义效果待验证。按失效层返回 L036–043，不直接添加更多框架。
**下一阶段：** P2 可成为 P3 的只读检索工具；独立 Agent loop 本身不以完成所有图检索扩展为硬性前置。

## M06｜Agent Loop 与可靠执行

### L045｜什么时候需要 Agent，而不是 Workflow
**前置：** L029、L034；接检索时使用 P2。
**问题与目标：** 明确任务、控制权与成功条件，再决定是否交给模型动态选择行动。
**教学顺序：** 单次调用→确定 workflow→模型驱动 loop→人工决策；比较动态性、测试难度、延迟、费用与风险。先列风险，后开放工具。
**练习与产物：** 为“固定字段抽取、文档问答、多步调查”设计三种最小方案；写成功、失败、终止和禁止行动条件，列对照基线。
**独立验收：** 说明 workflow 已经够用的反例；指出 Agent 不是“接了工具的模型”这一句话就能概括全部执行责任。
**错误与回补：** 不把自主性越高当产品价值越高。任务不清回 L035 的评估方法；下一课写 loop。

### L046｜不用编排框架隐藏核心 Loop
**前置：** L029、L045。
**问题与目标：** 将 model response、tool request、真实执行和观察结果分开。
**教学顺序：** 状态→模型调用→解析工具请求→执行器→tool result→状态更新→下一轮/终止；区分输出文本、执行日志与实际环境结果。
**练习与产物：** 用 deterministic fake model 和两个只读 mock 工具实现最小循环；测试正常完成、无工具、非法响应、超步数及取消，记录 trace。
**独立验收：** 解释谁负责真正执行工具；为什么模型声称“已发送”不能作为发送成功证据。
**错误与回补：** 不用固定脚本成功冒充真实自主能力。控制流不清先手写状态转移；下一课完善工具契约。

### L047｜Tool Contract、Schema 与授权
**前置：** L046；后端校验/身份经验。
**问题与目标：** 模型给出的参数不可信，工具接口必须同时可理解、可验证和可授权。
**教学顺序：** 工具名称/用途→输入 schema→服务端验证→身份与资源策略→执行结果/typed error→输出裁剪与敏感信息处理。
**练习与产物：** 为 P2 检索和一个 mock 写操作制定 contract；测试缺字段、越界值、超大参数、无权限与敏感结果；禁止模型自由指定可信 tenant identity。
**独立验收：** 说明 JSON 合法、参数合法、用户有权操作分别由谁判断；模型选中工具不等于授权通过。
**错误与回补：** 不把工具描述或 system prompt 当 IAM。身份链不清先修服务端边界；下一课处理失败重试。

### L048｜Timeout、Retry 与幂等副作用
**前置：** L046–L047。
**问题与目标：** 工具超时后不知道是否执行，不能简单再调一次。
**教学顺序：** 请求失败 vs 结果未知→可重试错误分类→backoff/截止时间→idempotency key→状态查询与补偿；读/写操作分别设计。
**练习与产物：** 在 mock 支付/通知中模拟“执行成功但响应丢失”；证明相同业务键重试不会重复副作用；记录无法保证 exactly-once 的边界。
**独立验收：** 解释重试为何可能更危险；给出一个不应自动重试的错误。
**错误与回补：** 不能仅靠内存布尔值跨重启保证幂等。契约不清回 L047；下一课处理恢复。

### L049｜Checkpoint、Resume 与持久化状态
**前置：** L048、后端事务基础。
**问题与目标：** 保存聊天消息不等于系统可恢复，也不等于外部副作用恰好一次。
**教学顺序：** task/run/step 状态→持久化边界→checkpoint→外部工具结果关联→崩溃恢复；按需要比较事务、outbox、幂等记录和补偿，不强行套用单一方案。
**练习与产物：** 在执行前、执行后记录前、checkpoint 后分别注入中断；恢复后检查任务状态和实际 mock 环境，保存故障时序表。
**独立验收：** 解释“checkpoint 成功”仍可能有什么未知；指出哪些保证需要外部系统配合。
**错误与回补：** 不把 replay 全消息等同于重做全部工具。副作用问题回 L048；下一课控制计划与预算。

### L050｜Planning、Routing、Context Router 与预算
**前置：** L041–L042、L046、L049。
**问题与目标：** 分清模型提出的计划、runtime 的实际状态和资源约束。
**教学顺序：** 分解/路由→计划验证→执行状态→上下文选择→token/step/时间/费用预算→终止/取消；Context Router 依据任务与权限选择信息，不是任意丢历史。
**练习与产物：** 在 P3 加入预算对象和终止原因；模拟循环调用、context 超限、任务取消与计划改写；检验恢复后预算不重置为无限。
**独立验收：** 说明 runtime 为什么不能只相信模型“我下一步就结束”；区分计划文本与真实完成状态。
**错误与回补：** 预算耗尽不能由模型自行忽略。状态不清回 L049；下一课审视不可信输入与高风险动作。

### L051｜Human Approval 与 Prompt Injection 边界
**前置：** L047–L050；工具从 L047 已有最低授权保护。
**问题与目标：** 深化外部内容影响模型判断后，怎样阻止越权副作用。
**教学顺序：** 来源/信任分级→文档与工具返回中的恶意指令→权限最小化→高风险动作提案→绑定具体参数的人工批准→执行前再次校验→审计。
**练习与产物：** 在 mock 环境测试越权请求、批准后参数被改、工具输出诱导泄密和过期批准；确认拒绝发生在执行器，而非仅依赖模型自我拒绝。
**独立验收：** 解释批准必须绑定谁、什么资源、什么参数和多长时效；安全措施不能只是一段提示词。
**错误与回补：** 不宣称几条对抗题通过等于绝对安全。身份/contract 缺陷回 L047，执行状态问题回 L049。

### L052｜Reflection、Multi-Agent 与复杂度对照
**前置：** L045–L051。
**问题与目标：** 判断增加反思、多模型或多 Agent 是改进，还是放大成本和错误传播。
**教学顺序：** 单 Agent/固定 workflow 基线→一次受限反思→角色/消息/共享状态→并发与冲突→工具/技能描述的装配→额外成本和可观测性。
**练习与产物：** 对同一小任务集比较最小基线与一种新增结构；保存任务成功率、步数、费用和失效案例。一次只引入一种复杂化，不同时换模型、prompt 和框架。
**独立验收：** 解释何时值得多个 Agent，何时一个确定流程更可靠；指出重复角色不自动产生独立判断。
**错误与回补：** 不用协作对话看起来热闹当证据。对照设计不足回 L035；下一课 P3 第一版验收。

### L053｜P3 Runtime 故障注入验收
**前置：** L045–L052；结合 P2 时 L044 已有通过证据。
**问题与目标：** 证明 runtime 不只会跑 happy path。
**练习与产物：** 用固定 fake provider 逐项测试非法参数、超时、重复响应、进程重启、取消、预算耗尽、越权与批准失效；检查最终环境状态，提交最小 loop、状态图、测试矩阵与 runbook 初稿。
**独立验收：** 给未知失败案例区分 model/retrieval/tool/runtime 层；说明模型质量试验与确定性执行测试为什么必须分开。
**错误与回补：** 能继续运行不等于没有重复副作用；追踪日志不等于通过任务。按故障层回 L046–051，不用更换框架逃避机制错误。
