## M03：完整 Transformer 与语言建模闭环（续，D031–D036）

### D031｜Hidden States、LM Head 与 Vocabulary Logits
**前置/目标：** D023/D030；解释 N×d_model 的表示如何成为每个位置上的词表预测。
**讲解链：** 最后一层 hidden representation → LM head 线性映射 → vocabulary logits → 目标 token 概率与 Loss；词表大小不是 embedding 宽度，输出 Softmax 与 Attention Softmax 的对象不同。
**练习/交付：** 用小词表实现 LM head，标注 B/N/D/V 四种轴；对指定位置计算目标 token Loss。记录是否共享 embedding/output 权重，不把共享当作必须。
**验收/追问：** 相同 hidden width 下词表翻倍，输出 shape 哪部分改变？为什么 token 数量与每个 token 的候选词数不能混淆？
**回补/衔接：** 分类目标回 D023，表示回 D008；随后 D032。

### D032｜语言模型数据：Label Shift、Packing 与 Mask
**前置/目标：** D007/D011/D024/D031；能从语料构造正确输入与目标，防止训练泄漏。
**讲解链：** 序列里的下一个 token 作为监督目标 → 输入/标签错位 → causal 可见性 → padding/ignore loss → 文档边界与 packing 策略；不同实现可能在模型或数据侧执行 shift，要确认只做一次。
**练习/交付：** 对短序列逐位置列出 input、可见上下文、target、是否计入 Loss；建立文档级划分与去重检查，测试 padding 与跨文档边界。
**验收/追问：** 模型若看见了自己应预测的 token，会怎样“作弊”？把两篇文档拼起来是否可以不说明边界策略？
**回补/衔接：** 信息可见性回 D011，泄漏回 D024；随后 D033。产物：可审查 batch 示例及标签断言。

### D033｜P1：拼装一个微型 Decoder-only Transformer
**前置/目标：** D014/D027–D032；把学过的组件组织成完整可运行前向模型。
**讲解链：** token lookup/位置 → 一到两层 Attention+FFN+Residual+Norm → LM head；配置和结构选择逐项明确，不以调用完整 Transformer 黑盒替代组件理解。
**练习/交付：** 在小维度、短序列配置下实现 forward；每层保留 shape 断言，使用合成输入做 mask、padding 和输出尺寸测试。设备默认 CPU，规模由实际资源约束。
**验收/追问：** 能指出任意张量从哪里来、到哪里去；删除残差或 mask 后哪些性质会变化？
**回补/衔接：** 缺哪个组件就回对应单元；随后 D034。产物是可测试教学模型，不要求此时生成流畅语言。

### D034｜P1：训练、验证与第一份误差分析
**前置/目标：** D026/D032/D033；完成数据到参数更新的闭环，而不是只展示 Loss 数值。
**讲解链：** 正确 batch → forward/Loss → backward/update → 验证 → checkpoint；先以小样本过拟合检查可学习性，再用独立验证集讨论泛化。
**练习/交付：** 训练 tiny LM，记录配置、种子、有效 token 数与 train/validation Loss；检查关键矩阵梯度；保留一种失败并定位到数据、目标、图路径或优化设置。
**验收/追问：** 为什么小训练集上能够过拟合是排错线索，却不是产品能力证明？Loss 不降时为什么不能首先只加大模型？
**回补/衔接：** 循环回 D021，目标回 D032，泛化回 D024；随后 D035。

### D035｜P1：Checkpoint、恢复与自回归生成
**前置/目标：** D022/D034；区别训练可并行预测位置和生成必须逐步获得新 token。
**讲解链：** 已知训练序列提供多个目标 → 生成时只给已有前缀 → 取新 token 再扩展输入；保存模型/配置/tokenizer/必要优化器状态，区分恢复训练和只做推理。
**练习/交付：** 保存加载后比较同一输入的 logits；实现最简单 greedy 生成及停止长度；恢复训练时检查状态与步数，记录随机性边界。
**验收/追问：** 训练预测多个位置为什么不代表生成未来 token 可以不依赖前面结果？只保存权重能否重建全部实验？
**回补/衔接：** 优化器状态回 D022，mask/目标回 D032；随后 D036。

### D036｜P1 门槛：完整 Transformer 解释、实现与排错
**前置/目标：** D027–D035；确认已掌握的范围是可解释的微型模型闭环，而非大规模预训练。
**练习/交付：** 从一段文本独立追踪到 token、embedding、block、logits、Loss、梯度、更新和生成；重跑未来扰动测试；修复一个标签移位或归一化轴错误。
**验收/追问：** 提交可运行入口、锁定配置、测试、训练/验证记录和一份失败分析；分别验证架构、训练、推理三种表达，不能用背一条箭头链替代。
**回补/衔接：** 以失败归因回 D026/D029/D032/D034；通过后 D037。本日作为复习与补实验缓冲，不新增架构。

## M04：模型调用、推理性能与适配（D037–D044）

### D037｜模型接口、Prompt 与 Structured Output
**前置/目标：** D031/D036；建立应用层契约，区分输入上下文、模型权重与执行结果。
**讲解链：** messages/角色/数据边界 → 输出 schema → 校验/错误 → 调用方处理；prompt 改变通常不是更新参数，合法 JSON 也不代表事实正确或操作已执行。文本、图像等输入能力须按所用模型契约核验。
**练习/交付：** 定义可替换的模型接口和 deterministic fake，覆盖正常、格式错误、拒答、超时、流式中断；对同一任务比较明确 schema 与自由输出。
**验收/追问：** 模型返回“已保存”是否能当作数据库写入成功？为什么 schema 验证不替代业务验证？
**回补/衔接：** logits/生成回 D031/D035；随后 D038。产物：接口契约与测试，默认不需要付费模型。

### D038｜生成策略与随机性
**前置/目标：** D004/D035；理解 greedy、temperature、Top-K/Top-P 和停止条件的行为差别。
**讲解链：** logits 到分布 → 调整分布 → 候选截断 → 采样/贪心 → EOS/长度停止；随机性不等于创造力，temperature 也不是事实正确性的保证。
**练习/交付：** 在固定 logits 和多个种子下比较策略，再用 P1 生成样例；记录候选集、输出长度与重复，避免不同模型/不同 prompt 混在一起比较。
**验收/追问：** Top-P 与固定 Top-K 的候选数为何不同？降低温度是否能消除幻觉？
**回补/衔接：** 概率分布回 D004；随后 D039。产物：同条件生成对照表与合理停止策略。

### D039｜Prefill、Decode 与 KV Cache
**前置/目标：** D010/D035；把生成链路连接到服务延迟和显存成本。
**讲解链：** 已知前缀处理 → 每步新增 token → 复用已有 Key/Value → cache 生命周期；区分缓存中间表示、保存聊天记录和训练参数。cache 策略与模型结构/服务实现相关。
**练习/交付：** 给 P1 实现最小 cache 或做逐步张量追踪，比较带/不带 cache 的 logits；在固定长度、batch、dtype 下记录时间与缓存规模。
**验收/追问：** 为何通常不是只保存最终回答文本？长上下文下，减少重算为何仍不能让显存成本消失？
**回补/衔接：** Attention 来源回 D010，生成回 D035；随后 D040。无设备测量时只报理论估算，不编加速倍数。

### D040｜RoPE、MHA/MQA/GQA 与长上下文边界
**前置/目标：** D012/D013/D039；理解工程变体改变了哪些张量和资源，而非背缩写。
**讲解链：** 位置如何进入 Q/K 关系 → RoPE 的旋转/相对偏移直觉 → Query 与 KV 头数的组合 → cache 体积与表达权衡。不能由编码公式可计算任意位置推出任意长上下文质量不降。
**练习/交付：** 对小配置列出 MHA/MQA/GQA 的 Q/K/V/cache shape；用二维 sin/cos 例子演示旋转和偏移，比较与加性 PE 的位置。
**验收/追问：** GQA 共享什么、不共享什么？为什么 context window 上限与可靠利用上下文的能力不是同一指标？
**回补/衔接：** 相位回 D012，头维度回 D013；随后 D041。变体公式依官方论文/实现核验。

### D041｜推理性能：测量、量化与 Attention 优化
**前置/目标：** D039/D040；建立吞吐、TTFT、每 token 延迟、峰值内存的可比口径。
**讲解链：** 先测瓶颈 → 分清算力/内存/调度 → batching 与缓存 → 量化的精度/内存权衡 → FlashAttention 的访存优化动机。优化实现不等于精确 Attention 的序列复杂度自动变成线性。
**练习/交付：** 固定模型、长度、并发和测量方法，完成一个资源允许的对照；无 GPU 时分析可靠测量记录或用 CPU 做正确性实验，明确不能外推 GPU 性能。
**验收/追问：** 两个吞吐数字若 batch 不同能直接比较吗？只看平均延迟会漏掉什么？
**回补/衔接：** cache 回 D039；随后 D042。产物：测量配置、原始数据、限制说明。

### D042｜Pretraining、SFT 与 LoRA/PEFT
**前置/目标：** M02/D036；分清训练目标、训练数据和哪些参数被更新。
**讲解链：** 基础语言建模 → 指令/任务监督 → 全参数与参数高效适配 → LoRA 的低秩增量直觉 → 数据质量与验证；微调不是可靠的实时知识数据库。
**练习/交付：** 在一个小线性层实现低秩增量，检查冻结基础权重、可训练参数数目和梯度；设计一份含训练/验证分离的 SFT 数据契约，不要求训练大模型。
**验收/追问：** 冻结基座后为什么仍能改变输出？更适合改 prompt、加检索还是训练增量，需要什么证据？
**回补/衔接：** 冻结/梯度回 D025，目标回 D015/D023；随后 D043。

### D043｜偏好优化、对齐与适配风险
**前置/目标：** D024/D042；能够解释 SFT、RLHF/DPO 的目标差异与工程边界，不要求推导全部强化学习算法。
**讲解链：** 示范答案与偏好对 → 奖励/偏好信号 → 优化行为 → 评价偏差与 reward hacking 风险 → 安全和任务表现的多维验证。训练目标改善不等于所有业务指标改善。
**练习/交付：** 对一个客服或阅读任务写出示范、偏好对、拒绝/越权反例；提出独立于训练标签的验证规则，分析一个偏好数据有偏的情境。
**验收/追问：** 人类更喜欢的答案可能在哪些方面仍不可靠？没有完整训练实验时能声称对齐更好吗？
**回补/衔接：** 目标与泛化回 D024；随后 D044。实现深度限定为解释和选型，完整 RL 优化作为扩展。

### D044｜模型应用选型门槛与缓冲
**前置/目标：** D037–D043；把机制转成一份有证据的应用设计，而非追逐模型名称。
**练习/交付：** 为“有新知识、固定格式、成本受限、需隐私保护”的任务写 Prompt/RAG/SFT/LoRA 决策记录，列假设、基线、测量、失败条件和回退；演示一次格式错误与超时处理。
**验收/追问：** 为什么不直接微调解决全部问题？模型或 SDK 换版本时哪些测试必须重跑？
**回补/衔接：** 按缺口回 D037/D039/D042/D024；通过后 D045。产物进入 ADR，不把计划中的性能改善写成实验事实。

## M05：可评测 RAG、Context 与 Memory（D045–D057）

### D045｜P2 需求、数据边界与评测集先行
**前置/目标：** D024/D037；先定义什么叫回答成功，再搭检索流水线。
**讲解链：** 用户问题 → 所需证据 → 数据授权/范围 → 可回答与不可回答 → 成功标准；离线 ingestion 与在线 query 分离。Evaluation 和权限从第一天设计，不等最后补。
**练习/交付：** 选合成或已授权的小文档域，编写起步问题集，覆盖直接事实、跨段、无答案、冲突、越权；每例记录来源与预期行为。20–40 例可作教学起点，不声称统计充分。
**验收/追问：** 系统回答得流畅但没有证据是否成功？某题没有唯一答案时如何避免错判？
**回补/衔接：** 目标与划分回 D024；随后 D046。产物：P2 的数据与评价契约。

### D046｜文档解析、身份、版本、更新与删除
**前置/目标：** D045；让检索证据可追溯，而不是只存一堆无法定位的文本片段。
**讲解链：** 原始文档 → 结构解析 → 稳定 document ID/version/source span → 下游索引；区分正文、标题、表格/图片证据、页码与元数据。图像/OCR 或多模态解析须按实际数据需求选择，不默认全部转纯文本无损。
**练习/交付：** 解析三种结构样本并保留出处；模拟文档更新与删除，列出向量、倒排、图、缓存需要同步处理的对象。
**验收/追问：** 同名新版本为什么不能盲目复用旧 chunk？文档删除后回答仍引用旧内容如何排查？
**回补/衔接：** 数据身份不清回 D045；随后 D047。

### D047｜Chunking 与信息边界
**前置/目标：** D007/D046；比较切块策略而不是背一个最佳长度。
**讲解链：** 长文超出检索/上下文预算 → 切块 → 边界导致信息割裂 → overlap/层级结构/元数据补偿；重复片段会影响成本与评测。
**练习/交付：** 同一资料做固定长度与结构感知两种切块；检查条件句、表格解释、跨段引用，记录丢失和重复；在固定问题集上比较证据是否完整。
**验收/追问：** chunk 越大是否总能提升回答质量？overlap 增大可能付出什么代价？
**回补/衔接：** token 计量回 D007，解析边界回 D046；随后 D048。产物：切块对照和失败样例。

### D048｜检索 Embedding、相似度、ANN 与过滤
**前置/目标：** D003/D008/D047；区分语义表示、近邻索引与访问过滤的作用。
**讲解链：** query/document 向量 → 距离或相似度 → 归一化的影响 → 精确检索基线 → ANN 的速度/召回权衡 → metadata/ACL 过滤；语义相似不等于事实支持。
**练习/交付：** 用小向量集手算 dot/cosine，建立精确检索基线，再比较一种可用 ANN；记录 embedding 模型版本与维度，测试过滤前后候选。
**验收/追问：** 更换 embedding 模型为什么通常不能让新 query 直接混用旧向量库？过滤位置为何可能影响召回？
**回补/衔接：** 向量与归一化回 D003/D004；随后 D049。产物：版本化索引契约与检索结果表。

### D049｜Sparse、Dense 与 Hybrid Retrieval
**前置/目标：** D048；理解不同检索方式各自的失败模式和组合动机。
**讲解链：** 精确词项与标识符 → sparse/BM25；语义改写 → dense；两种候选 → 融合排序；分数尺度不兼容时不能直接随意相加。
**练习/交付：** 固定含产品编号、同义表达、罕见实体的问题集，对比 sparse、dense、hybrid；先保存候选与命中证据，再看最终回答。
**验收/追问：** 为什么看似先进的向量检索也可能输给词项检索？融合增加召回时可能增加哪些误召回？
**回补/衔接：** 相似度回 D048；随后 D050。产物：三策略同条件对照，不预设 hybrid 必胜。

### D050｜Query 改写、Reranking 与召回/精排分工
**前置/目标：** D049；理解漏召回与错排序不同，避免一个“Top-K”覆盖所有阶段。
**讲解链：** 原问题/对话指代 → 受约束改写 → 第一阶段候选 → rerank → 选择证据；区分 retrieval K 与最终 context K，以及 recall/precision 的权衡。
**练习/交付：** 记录改写前后 query 与结果，检查改写是否引入未给条件；为同一候选比较原排序与重排，分开统计召回失败和排序失败。
**验收/追问：** 正确文档根本没被召回时，reranker 能补救吗？增加 K 对延迟、噪声和上下文预算有什么影响？
**回补/衔接：** 候选生成回 D049；随后 D051。

### D051｜Context 构建、压缩、引用与拒答
**前置/目标：** D037/D050；把检索结果变成可验证的模型输入，而不是全部塞进 prompt。
**讲解链：** 证据选择 → 去重/排序 → token budget → 带出处组装 → 输出引用与证据校验 → 无证据/冲突时的行为；摘要可能丢失限定条件，长上下文不是可靠利用证据的保证。
**练习/交付：** 对相同候选做两种 context 组装；设计一个必须保留否定/时间条件的压缩测试；验证引用能定位原文，无答案时不捏造。
**验收/追问：** 答案引用了一个文件就足以证明句子受支持吗？证据互相矛盾应如何表达不确定性？
**回补/衔接：** 文档出处回 D046，预算回 D007；随后 D052。

### D052｜Context、Conversation History 与 Memory
**前置/目标：** D051；建立记忆写入、检索、冲突、删除的工程模型，不把所有对话无限追加。
**讲解链：** 当前窗口与历史存储分离 → 工作状态/事件记录/长期事实 → 写入门槛 → 检索相关性与时效 → provenance/TTL/冲突策略；存入记忆不等于更新模型权重。
**练习/交付：** 为阅读系统或 Agent 设计一份 memory schema，含来源、时间、主体、置信证据与删除规则；测试用户纠正旧事实、撤销授权和无关记忆不应注入。
**验收/追问：** 模型生成的猜测能否直接当长期事实保存？清除聊天窗口是否等于删除全部记忆？
**回补/衔接：** 模型参数边界回 D037；随后 D053。产物：写/读/更新/遗忘策略与测试。

### D053｜RAG 权限、隐私与 Prompt Injection 边界
**前置/目标：** D046/D051/D052；让证据来源与指令权限分开，验证隔离而非靠提示词承诺。
**讲解链：** tenant/user identity → 解析与索引授权元数据 → query 时强制 ACL → context/缓存/日志隔离；检索文档是数据，不获准覆盖系统权限；删除需要跨派生存储落实。
**练习/交付：** 构造两个租户文档与越权问题，检查检索、引用、缓存、日志；加入一段诱导工具越权的文档并验证执行器拒绝，不执行真实危险命令。
**验收/追问：** 为什么向量库过滤正确仍可能在共享缓存泄漏？Prompt 中写“禁止越权”能否代替服务端授权？
**回补/衔接：** 数据生命周期回 D046，引用组装回 D051；随后 D054。

### D054｜RAG 分层评估与错误归因
**前置/目标：** D045–D053；用固定用例识别系统变更究竟改善了哪一层。
**讲解链：** parsing → retrieval → rerank → context → generation；分别测证据命中、排名、支持度、引用、拒答、延迟/成本。平均分之外必须看类别与失败样例。
**练习/交付：** 建立可重跑评估命令；保存每层中间结果；对一批错误标注首个失败环节；用人工标注核对自动 grader 的一致性。
**验收/追问：** 给模型正确证据后仍答错，能否继续只调整 chunk？LLM judge 说正确是否可作为唯一依据？
**回补/衔接：** 对应层缺口回对应日；随后 D055。产物：P2 分层报告与版本化问题集。

### D055｜GraphRAG / LightRAG 的数据流与成本
**前置/目标：** D046/D054；解释图检索的额外表示、适用问题和代价。
**讲解链：** 文本片段 → 实体/关系抽取 → 合并与来源 → 图/向量检索 → 证据组装；区分抽取的关系与可靠事实，图上有路径不等于证据链成立。
**练习/交付：** 固定一个实际 LightRAG 版本，阅读其入库和查询入口；选小语料检查实体冲突、关系出处、更新与删除路径。用户实际项目源码未提供时仅研究官方实现，不声称已审查私有系统。
**验收/追问：** 哪类跨段问题可能值得图结构，哪类不值得？抽取错误怎样传递到答案？
**回补/衔接：** 数据与评估回 D046/D054；随后 D056。

### D056｜P2：普通 RAG 与图方案对照实验
**前置/目标：** D055；以相同任务评估增加图复杂度是否值得。
**讲解链：** 固定语料与问题 → 普通 RAG 基线 → 图方案 → 同口径证据/答案/成本 → 按问题类别归因。禁止同时更换模型、prompt、数据再把收益归给图。
**练习/交付：** 复用 P2，比较一组直接事实题与跨关系题，记录抽取成本、查询延迟和失败案例；资源不足则用明确标记的最小手工图实验验证机制，不伪装完整性能评测。
**验收/追问：** 图方案总分略高但成本显著增加时如何做选型？小样本差异可以推广到百万文档吗？
**回补/衔接：** 对照设计回 D054；随后 D057。产物：检索方案 ADR。

### D057｜P2 门槛：可评测、可溯源、可隔离的 RAG

**练习/交付：** 演示入库→查询→引用→无答案→更新/删除→越权拒绝；重跑固定评测集；接受一条新文档和一个失败案例并定位原因。

## M06 起始：Agent 与工具执行（D058–D060）

### D058｜Workflow、LLM+Tools 与 Agent 的控制流
**前置/目标：** D037；接检索工具时依赖 P2，但构建不含检索的 Agent 并不要求先学会 RAG。
**讲解链：** 固定程序流程 → 模型选择工具或下一步 → 环境反馈 → 状态与停止；Agent 不是模型自己获得操作系统权限，多 Agent 也不自动更好。
**练习/交付：** 为同一教学任务写固定 workflow 与 Agent loop 的状态草图，用 deterministic fake 模型模拟选择和终止；定义预算与成功环境状态。
**验收/追问：** 哪些任务固定 workflow 更可靠？模型返回 tool request 与工具已成功执行差在哪一层？
**回补/衔接：** 输出契约回 D037；随后 D059。产物：P3 场景与最小控制流，不先引入大型框架。

### D059｜Tool Contract、Schema 与错误协议
**前置/目标：** D058；将后端接口经验迁移到不可靠的模型调用方。
**讲解链：** 工具描述与输入 schema → 类型/业务校验 → 可执行动作 → 结构化成功或错误 → 模型能理解的返回；工具 schema 不等于业务授权。
**练习/交付：** 定义只读检索工具与 mock 写操作工具；覆盖缺参、类型错、参数越界、无结果、上游故障、超大返回；SQL 示例使用参数化查询与只读权限，不开放任意 SQL/命令执行。
**验收/追问：** 非法参数应交给模型猜测补救，还是执行器先拒绝？错误消息怎样既可恢复又不泄漏秘密？
**回补/衔接：** 接口边界回 D037/D058；随后 D060。

### D060｜授权、人工批准与副作用边界
**前置/目标：** D053/D059；在第一个有副作用工具之前完成确定性的安全边界。
**讲解链：** 提议动作 → 身份与策略判断 → 参数及风险核验 → 必要时人工批准 → 执行 → 结果记录；批准要绑定具体动作/参数，不能让模型自由扩大授权。
**练习/交付：** 为 mock 写操作设计批准状态与一次性执行凭据；测试未批准、批准后改参数、过期、重复请求、越权主体和取消。此日只用模拟副作用，幂等实现于 D062 深化。
**验收/追问：** 模型在 prompt 中声称“用户同意”可否当授权？为什么一次批准不能无限授权之后所有写操作？
**回补/衔接：** 身份/数据边界回 D053，工具参数回 D059；随后第三册 D061，开始实现可靠 Agent loop。
