## M06：可靠 Agent Runtime（续，D061–D067）

### D061｜实现 Agent Loop 与显式状态机
**前置/目标：** D058–D060；写出不被框架隐藏的模型—工具—反馈闭环。
**讲解链：** 接收任务 → 组装状态/消息 → 模型响应 → 解析工具请求 → 校验/授权 → 执行 → 记录结果 → 继续或终止；区分任务状态、对话消息、工具调用状态。
**练习/交付：** 用 deterministic fake 实现至少一次成功工具调用、多步调用、模型直接回答、非法响应和达到步数上限；每个状态转换可追踪。
**验收/追问：** 执行器失败后是谁决定是否继续？为什么没有终止条件的 while-loop 不是可靠 Agent？
**回补/衔接：** 控制流回 D058，工具契约回 D059；随后 D062。产物：P3 的最小可测试循环。

### D062｜Timeout、Retry、Idempotency 与取消
**前置/目标：** D060/D061；区分调用重试与副作用去重，迁移后端可靠性经验。
**讲解链：** 暂时故障/永久错误分类 → 超时预算 → 退避重试 → 幂等键与结果记录 → 取消传播与补偿；网络超时不等于远端没有执行。
**练习/交付：** 对 mock 写工具模拟“执行成功但响应丢失”，确保简单重试不重复写；覆盖重复回调、请求取消、重试耗尽和不可重试错误。
**验收/追问：** 去重记录先写还是副作用先发生，各有什么窗口？为什么不能随口承诺任意外部系统 exactly-once？
**回补/衔接：** 授权回 D060，状态流回 D061；随后 D063。产物：幂等设计、失败时间线与测试。

### D063｜Checkpoint、恢复与持久化执行
**前置/目标：** D061/D062；让任务中断后可恢复，而不是只把 messages 保存下来。
**讲解链：** durable task state → 待执行/执行中/已确认动作 → checkpoint 与外部副作用边界 → replay/resume → 状态迁移；能重放不等于所有动作可以安全再执行。
**练习/交付：** 在工具执行前、执行后但记录前、记录后三个点模拟进程退出，再恢复；验证审批、幂等键、工具结果和预算不丢失。
**验收/追问：** 什么状态必须持久化才能判断下一步？已批准的动作在恢复时参数改变应如何处理？
**回补/衔接：** 副作用窗口回 D062；随后 D064。产物：故障注入记录和恢复状态转换表。

### D064｜Context Router、记忆与执行预算
**前置/目标：** D051/D052/D061；把上下文选择和资源控制做成可检查的 runtime 逻辑。
**讲解链：** 当前任务/工具状态 → 相关历史与证据 → context budget → 返回长度控制/压缩 → step/token/time/cost 上限 → 停止或降级。压缩必须保留关键约束、批准与未完成事项。
**练习/交付：** 为 P3 实现可替换 context builder，测试大工具输出、冲突记忆、预算耗尽与上下文截断；用计数器和 fake 价格做预算单测，不伪造真实账单。
**验收/追问：** 历史摘要漏掉“不得写入”会有什么后果？模型声称还要一步就完成时，是否能越过执行器预算？
**回补/衔接：** 记忆策略回 D052；随后 D065。产物：Context Router 契约与预算测试。

### D065｜Planning、Reflection 与 Multi-Agent 的边界
**前置/目标：** D061–D064；学会判断何时复杂化，而非默认多个 Agent 更智能。
**讲解链：** 单 Agent/固定 workflow 基线 → 任务分解 → 计划修订 → 反思触发 → 多 Agent 通信和状态合并 → 成本、错误传播与终止。
**练习/交付：** 对同一小任务设计单 Agent 与一次受限分工版本，用相同成功标准比较；分析冲突结论、重复工作与无限讨论，设定明确退出条件。
**验收/追问：** 哪种瓶颈可能值得分工，哪种只会增加协调成本？增加“反思”步骤为什么可能让正确答案变差？
**回补/衔接：** 预算回 D064，评测目标回 D045；随后 D066。产物：是否采用复杂流程的 ADR。

### D066｜框架映射与同任务对照
**前置/目标：** D061–D065；在理解机制后选择一种框架验证抽象边界。
**讲解链：** 自写 loop 的状态/执行/恢复契约 → 候选框架的对应抽象 → 能复用的基础能力 → 隐藏的限制；只选择一种与任务匹配且实施时仍维护的框架，不并学多个 API。
**练习/交付：** 查当日官方文档，固定一个版本，把 P3 的一条最小流程迁移并跑同一组测试；比较恢复、幂等、审批、可观测性和可替换性，而非只比代码行数。
**验收/追问：** 哪些正确性仍由业务代码负责？框架提供 checkpoint 为什么不自动替你解决任意工具副作用？
**回补/衔接：** 先补对应机制，不为适配框架重写整套需求；随后 D067。无合适框架也可提交有证据的不采用决定。

### D067｜P3 初版门槛：可靠执行，而非只跑通 Demo
**前置/目标：** D058–D066；独立交付能在失败条件下说明行为的 Agent runtime。
**练习/交付：** 演示工具成功、非法参数、未批准、超时、重复请求、中断恢复、预算耗尽；以环境最终状态验证成功，不只看模型最后一句话。
**验收/追问：** 提交 loop、工具契约、状态/授权/幂等测试、运行入口和一份故障分析；说明哪些已被测试、哪些只是设计，不能宣称系统绝对可靠。
**回补/衔接：** 失败映射回 D059–D066；通过后 D068。本日含回补缓冲，框架选型不是通过的必要前提。

## M07：MCP、Harness 与 Sandbox（D068–D073）

### D068｜MCP 的架构与协议边界
**前置/目标：** D059/D067；解释 host/client/server 的职责和协议解决的问题。
**讲解链：** 模型应用连接外部工具/资料的重复适配 → host/client/server → tools/resources/prompts → 初始化/能力协商 → 请求与响应；MCP 不等于模型、更不等于拥有业务授权的 Agent。
**练习/交付：** 用固定规范版本追踪一次发现与调用，标出 host、client、server 与执行器；将普通工具接口映射到协议层，明确哪些业务职责未被替代。
**验收/追问：** 协议支持一个工具是否意味着当前用户有权调用？MCP server 与 sandbox 是否必然是同一个进程？
**回补/衔接：** 工具契约回 D059；随后 D069。资料：MCP 官方规范，实施前重新核验版本。

### D069｜Transport、身份、授权与凭证边界
**前置/目标：** D060/D068；区分传输机制、协议认证与业务授权。
**讲解链：** 进程内外连接/网络 transport → 客户端与服务身份 → token audience/scope 等约束 → 用户授权 → server 内业务策略；不能把一个版本的流程套给所有 transport，也不把任意凭证向下透传。
**练习/交付：** 画一条调用链的身份和信任边界，记录所用规范/SDK/transport；测试无凭证、错误主体、scope 不足、过期和拒绝响应，不使用真实生产密钥。
**验收/追问：** 成功建立连接为何不等于有权执行全部 tools？模型看到的数据为什么不应包含底层 secret？
**回补/衔接：** 授权回 D060，协议角色回 D068；随后 D070。

### D070｜MCP 工具适配与生命周期实验
**前置/目标：** D068/D069；给已有工具加协议适配而不改变其安全契约。
**讲解链：** 原工具 schema → SDK server 适配 → client 调用 → timeout/cancel/error → 清理与重连；协议边界的错误要映射回 runtime 能处理的类型。
**练习/交付：** 暴露 P2 的只读检索工具或 mock 工具；测试发现、调用、错误参数、连接中断、取消和资源释放；保留规范、SDK、代码与测试版本。
**验收/追问：** 取消请求到达后远端是否一定已经停止副作用？版本不匹配时应降级还是拒绝，依据是什么？
**回补/衔接：** 协议回 D068/D069，取消/幂等回 D062；随后 D071。

### D071｜Harness 的职责与可替换边界
**前置/目标：** D064/D070；明确本项目中 Harness 指围绕模型的执行支撑层，而非某个固定产品名。
**讲解链：** model decision → context/tool adapter → runtime/state/recovery/budget → policy → evaluation/trace；区分模型、编排框架、MCP、Harness 和 sandbox。
**练习/交付：** 为 P3 写组件契约和依赖关系：更换模型、工具协议或执行环境时哪些模块应改变；给一个组件替换后重跑原测试。
**验收/追问：** 把模型换强后哪些可靠性与权限问题仍然存在？为什么 MCP 不能独自承担整个 Harness？
**回补/衔接：** loop 回 D061，context 回 D064；随后 D072。产物：架构分层图的文字/图形表示和替换实验。

### D072｜Sandbox 威胁模型与资源生命周期
**前置/目标：** D060/D063/D071；根据威胁选择隔离，不把“运行在容器里”当作绝对安全证明。
**讲解链：** 不可信代码/工具输入 → 文件、进程、网络和身份边界 → CPU/内存/时间/磁盘配额 → 创建/回收/artifact → 容器与 microVM 的取舍；隔离仍依赖配置和宿主系统。
**练习/交付：** 为教学执行器列允许与禁止能力，使用受控模拟或已有隔离环境验证只读路径、网络白名单、时间/资源上限和清理；不做真实逃逸攻击，不在生产执行未知代码。
**验收/追问：** 只限制 CPU 为什么不够？结果 artifact 与临时文件在租户隔离和清理上应如何区分？
**回补/衔接：** 身份/副作用回 D060/D063；随后 D073。产物：威胁模型、配置边界与安全测试。

### D073｜协议与执行边界门槛
**前置/目标：** D068–D072；串联模型请求到隔离执行的完整可信路径。
**练习/交付：** 从一条 MCP tool call 追踪身份、schema、业务授权、批准、执行环境、结果和审计；注入一次无权访问、一次取消、一次资源超限，验证拒绝与清理。
**验收/追问：** 解释每个安全决定由谁执行、依据哪份状态；说明哪些是确定性测试、哪些是尚未验证的设计。运行 mock 的结果不得冒充真实 microVM 安全测评。
**回补/衔接：** 按边界失败回 D069/D070/D072；通过后 D074。本日含协议版本复核和回补缓冲。

## M08：Evaluation、企业架构与可靠性（D074–D080）

### D074｜Testing、Observability 与 Evaluation
**前置/目标：** D054/D067；将已有 tracing 优势扩展为系统化质量验证。
**讲解链：** 单元正确性 → 执行轨迹可观察 → 任务结果是否达到目标 → task/trial/grader/trace/outcome；看到每个调用成功不等于任务成功。
**练习/交付：** 给同一个 Agent 任务分别写单测、trace schema、能力评测；定义初始环境与最终期望状态，并记录模型、prompt、工具和数据版本。
**验收/追问：** trace 没报错为何仍可能任务失败？一个 LLM 文本评分为什么不能代替数据库状态检查？
**回补/衔接：** 分层评测回 D054，任务状态回 D061；随后 D075。

### D075｜Grader、人工校准与不确定性
**前置/目标：** D004/D024/D074；判断评测信号是否可信，不把 judge 当事实来源。
**讲解链：** 可确定的 code grader → 主观部分的 rubric/model grader → 人工校准 → 误报/漏报 → 重复 trial 与区间/样本量意识；区分任务歧义、评分错误和模型错误。
**练习/交付：** 人工标注一小组输出，对照自动评分并分析分歧；对固定任务重复运行，报告样本数、成功数和不确定性，而非单次漂亮百分比。
**验收/追问：** judge 偏爱冗长回答怎么办？同一个失败源污染全部 trial 时还能当独立样本吗？
**回补/衔接：** 基础统计回 D004，数据泄漏回 D024；随后 D076。

### D076｜Agent Outcome、Trajectory 与回归套件
**前置/目标：** D074/D075；同时评估任务成功、约束遵守和执行代价。
**讲解链：** 最终环境状态 → 关键安全/预算约束 → 必要轨迹检查 → 多次成功率 → capability 与 regression suite；不把唯一工具顺序硬编码成所有正确解的标准。
**练习/交付：** 对 P3 建立正常、拒绝、恢复、权限和成本分类套件；每个 trial 重置状态，避免缓存或文件残留泄漏答案；解释至少一次成功与每次都成功的差别。
**验收/追问：** 最终成功但越权是否算通过？一套已全部通过的回归题还能测出多少新能力？
**回补/衔接：** grader 回 D075，副作用回 D062；随后 D077。产物：可重复运行的 Agent 评测命令与报告。

### D077｜Multi-Tenant、IAM、Secret 与数据全链路隔离
**前置/目标：** D053/D063/D073；将隔离从数据库扩展到 AI 系统的全部派生状态。
**讲解链：** tenant identity 贯穿入口 → task/context/index/cache/checkpoint/log/artifact → 授权与最小权限 → secrets 生命周期 → 审计和删除；不可由模型自行选择可信 tenant ID。
**练习/交付：** 为 P2/P3 做租户边界清单；测试跨租户缓存键碰撞、恢复错任务、共享日志泄漏和已撤销授权；保留拒绝证据。
**验收/追问：** 检索 ACL 正确为何仍可能泄漏？后台任务恢复时身份上下文应从哪里获得？
**回补/衔接：** 数据 ACL 回 D053，持久状态回 D063；随后 D078。产物：全链路隔离与 secret 流向表。

### D078｜Model Gateway、SLO、预算与降级
**前置/目标：** D039/D041/D062/D076；把模型质量与服务可靠性、费用一起纳入设计。
**讲解链：** provider adapter → rate limit/timeout/circuit breaker → routing/fallback → quality gate → cost budget → SLO；回退模型可能改变工具、上下文和输出契约，不应悄悄破坏安全边界。
**练习/交付：** 用 fake providers 注入限流、慢响应、格式差异与价格计数；定义延迟/成功率/预算目标、超限行为和可观测事件，测量平均与尾延迟。
**验收/追问：** 无限制重试为何可能放大故障和费用？便宜回退模型若不满足工具契约该怎样处理？
**回补/衔接：** 预算回 D064，接口回 D037；随后 D079。产物：gateway 设计与故障测试，不编真实价格。

### D079｜版本化评测、发布、在线监测与回滚
**前置/目标：** D076–D078；建立变更可追踪的发布流程。
**讲解链：** prompt/model/retriever/tool/config 版本 → 离线回归 → 分阶段发布 → 在线监测与人工反馈 → 回滚；A/B 需要流量与风险前提，教学项目先做离线或模拟流量。
**练习/交付：** 编写 CI 评估入口与发布清单；模拟 prompt 或模型变更造成质量回退，选择阻断或回滚；记录评测数据污染和漂移风险。
**验收/追问：** 只给模型文件打版本是否足够复现行为？线上点赞提高是否足以证明因果改进？
**回补/衔接：** 对照/统计回 D075，SLO 回 D078；随后 D080。

### D080｜企业可靠性门槛与事故演练
**前置/目标：** D074–D079；完成一次从症状到证据再到恢复的系统诊断。
**练习/交付：** 接受“引用正确率下降，同时工具超时增多”的故障场景；用数据区分模型、retrieval、tool、workflow 与基础设施原因；提出最小回滚和验证方案。
**验收/追问：** 提交时间线、trace、分层评测、影响范围、修复/回滚及回归用例；不能只给“换模型、调 prompt”之类无证据建议。
**回补/衔接：** 回到失败责任所在单元；通过后 D081。本日兼评测校准和回补缓冲，安全测试通过不宣称绝对安全。

## M09：综合项目与架构答辩（D081–D087）

### D081｜综合项目范围、业务成功与验收合同
**前置/目标：** P2/P3 与 M08 阶段证据；复用现有产物，不另起第三套重复代码。

### D082｜垂直集成：检索、模型、工具与持久状态
**前置/目标：** D081；从输入到证据、计划、批准、执行和结果形成一条可运行链路。

**练习/交付：** 集成一条端到端流程，用 fake 模型与 mock 写工具固定行为，再在预算允许时替换真实模型做质量对照；记录集成 bug 与责任层。
**验收/追问：** 检索结果中的指令为何不能直接变成执行授权？子组件超时后全链路如何停止或恢复？

### D083｜事实可溯源与行动可授权
**前置/目标：** D051/D060/D082；同时验证“说得有依据”和“做得有权限”。
**讲解链：** 证据支持某个事实 → 事实是否足以支撑动作 → 用户/策略授权 → 审批参数绑定 → 执行结果验证；事实正确不等于行动获准。
**练习/交付：** 构造证据充分但未获批准、获批准但关键证据不足、证据互相矛盾三类用例；检查引用、拒答、澄清和执行路径。
**验收/追问：** 一个高置信度模型判断能否越过审批？为什么“系统没有调用危险工具”也可能仍回答了不被授权的数据？
**回补/衔接：** 证据回 D051/D053，审批回 D060；随后 D084。

### D084｜故障注入、恢复与预算约束
**前置/目标：** D063/D078/D082；用实验检验架构承诺。
**讲解链：** 为模型、检索、工具、存储分别列失败 → 在关键提交窗口注入 → 恢复/补偿/拒绝 → 验证环境最终状态与费用上限。
**练习/交付：** 完成进程重启、工具已写但响应丢失、凭证撤销、provider 限流和预算耗尽五类安全模拟；记录每类预期与实际以及未覆盖风险。
**验收/追问：** 哪个测试能证明重试不会导致样例中的重复副作用？为什么仍不能泛化成任意第三方服务的 exactly-once 保证？

### D085｜质量、成本、延迟与消融比较

**验收/追问：** 性能提高但越权测试失败能否上线？何时应该删掉增加复杂度却没有证据收益的组件？
