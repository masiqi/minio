# D057｜P2 门槛：可评测、可溯源、可隔离的 RAG

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M05 · 前置：D045–D056

## 预习：复习地图

完整 RAG 能力不是“向量检索+一次模型调用”。要连接数据授权、解析、版本、切块、检索、精排、Context、引用、拒答、更新删除、隔离和评测。图方案是候选设计，不是本门槛强制赢家。

## 核心框架与场景

本次验收准备场景：先让系统回答有证据的问题；再加入无答案问题；更新原文版本；删除一条资料；最后由另一租户发起同样查询。每一步都应能解释哪些存储、索引和缓存改变，答案为什么允许或拒绝。

可运行入口证明能启动；分层报告说明效果；出处记录说明证据；ACL 测试说明所测边界；ADR 说明选型原因。它们是不同证据，不能用一张架构图全部替代。

## 易错边界

Demo 成功不代表更新删除和权限都正确。索引 ACL 通过也不保证共享缓存、日志和 Memory 无泄漏。所有承诺必须限定在实际测试范围，不能说绝对不会幻觉。

## 复习：先独立回答

1. 已删除文档仍被引用，如何从引用信息反查故障层？
2. 不采用 LightRAG 时，怎样证明不是“没学会图方案”？

## 动手与达标证据

按原卡演示入库→查询→引用→无答案→更新/删除→拒绝越权，并处理一个未见失败。保留实际代码、版本、报告和 ADR；没实现部分继续待完成。
