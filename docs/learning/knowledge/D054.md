# D054｜RAG 分层评估与错误归因

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M05 · 前置：D045–D053

## 预习：问题与知识地图

RAG 失败不能全部叫“幻觉”。分层链：解析是否保留证据 → 检索是否召回 → 精排是否靠前 → Context 是否完整选择 → 生成是否受支持。每层有自己的输入、输出和可检查指标。

## 核心框架与案例

本次例：某题正确段落未进入 Top-20，是召回侧线索；在 Top-20 中但未进入 Context，是排序/选择线索；正确完整证据已在 Context 中却答错，要检查生成指令、冲突处理与模型行为。还需回看解析和权限，不能只依据最后一步随意归因。

起步指标可包含证据命中、排名、主张支持、引用准确、适当拒答、延迟和成本。逐类别与失败样例比单个平均分更能指出缺口。人为注入正确证据可作诊断对照，不应混入最终真实检索评测分数。

## 易错边界

LLM Judge 也可能判断错误，需要人工校准和明确 rubric。评估数据、模型、prompt、索引和代码版本不固定，就难以比较变更。单次回答变化不一定来自检索调整。

2. 平均分上升但越权题失败，应该怎样解释？

## 动手与达标证据

建立可重跑命令，保存各层中间结果，人工标注首个可识别失败环节并核对 grader；报告不确定归因而非强行下结论。
