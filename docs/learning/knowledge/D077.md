# D077｜Multi-Tenant、IAM、Secret 与数据全链路隔离

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M08 · 前置：D053、D063、D073

## 预习：问题与知识地图

企业 AI 的租户隔离贯穿请求、任务、Context、索引、缓存、checkpoint、日志和 artifact。入口认证只是开始；可信 tenant identity 必须在派生状态和恢复流程中延续，不能由模型生成一个 tenant_id 就被当作事实。

## 核心框架与案例

本次故障：任务缓存用 task_name 作键，不含租户与身份范围。A 和 B 同名任务相撞，即使向量库权限正确，也可能读到另一租户的结果。类似问题会出现在 checkpoint 恢复、共享临时目录和日志查看接口。

为每个存储和调用列出：数据归属、可信身份来源、授权位置、读取路径、保留/删除规则和审计证据。Secret 要明确创建、注入、使用、轮换与撤销的生命周期，不进模型上下文和仓库。

权限可能在长任务执行中撤销，恢复时需要按策略重新核验，不把启动时权限永久保留。

## 易错边界

给数据库表加 tenant_id 不是全系统隔离完成。哈希缓存键不自动带来正确权限。日志脱敏不代表所有查询者都能看到全部元数据；数据删除要覆盖派生副本。
