# D062｜Timeout、Retry、Idempotency 与取消

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M06 · 前置：D060、D061

## 预习：按四个问题阅读

Timeout 是何时不再等；Retry 是失败后是否再尝试；Idempotency 是重复请求怎样避免重复副作用；取消是怎样传播停止意图。它们互相配合，但没有一个能自动替代另外三个。

## 核心框架与案例

本次时间线：客户端发出创建工单 → 服务端创建成功 → 响应丢失 → 客户端超时 → 重试。若每次都生成新工单，超时恢复就产生重复业务效果。稳定幂等键应绑定同一个业务意图与参数，并保存可查询的执行状态/结果；相同键不同参数应有明确拒绝策略。

先区分暂时失败、永久错误与结果未知，再选择退避、查询结果、补偿、人工处理或终止。总 deadline 与重试预算限制整个任务，不应每次重试都重新获得无限时间。

副作用与去重记录之间可能存在提交窗口；对外部服务，需要它的幂等或结果查询契约协作，不能凭本地字典承诺任意系统 exactly-once。

## 易错边界

网络超时不等于远端未执行。取消请求不等于撤销已完成副作用。非法参数和未授权不应原样无限重试。去重记录仅在内存中，进程重启后可能丢失。

## 复习：先独立回答

1. 写操作超时后，为什么不能简单换一个幂等键重试？
2. 取消到达时工单已创建，系统还能诚实承诺什么？

<details><summary>展开核对要点</summary>

新键可能代表新业务意图，无法去重旧请求。可停止尚未发生的后续动作、查询并报告实际状态，按明确业务规则补偿；不能声称已经自动撤销。

</details>
