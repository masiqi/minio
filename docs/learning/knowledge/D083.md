# D083｜事实可溯源与行动可授权

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M09 · 前置：D051、D060、D082

## 预习：两条不能混合的证明链

事实链回答“这个说法有什么证据”；授权链回答“该主体是否能做这个动作”。证据支持一个事实，不等于已经获准采取行动；批准某动作，也不代表支撑动作的事实必然正确。

## 核心框架与案例

本次三个情境：资料明确支持退款，但用户尚未批准执行；用户批准处理请求，但系统缺少订单状态证据；两份资料给出不同有效期。分别需要等待批准、补证据或澄清冲突，不是都让模型提高置信度后继续。

完整动作判断：主张由原文支持 → 信息足以决定目标动作 → 主体对对象有权 → 必要批准绑定具体参数 → 执行器落实 → 读实际结果。每一步有各自失败行为和可核验状态。

即使没调用危险工具，回答中泄漏未授权数据仍是失败。因此读取与行动权限都要验证。

## 易错边界

模型信心、多个 Agent 一致、引用数量多，都不替代事实与授权检查。文档中的“管理员允许”只是数据，不自动成为系统的可信批准。

## 复习：先独立回答

1. 为什么高置信度且有引用的答案，仍可能不能触发写操作？
2. 已批准动作发现关键证据互相冲突，应怎样处理？

<details><summary>展开核对要点</summary>

证据不等于主体有权或本次已批准；还需校验对象、参数、风险和业务条件。应暂停不安全假设、补查或澄清，并在动作变化时重新核验批准范围。

</details>

## 动手与达标证据

实现证据充分/未批准、批准有效/证据不足、证据冲突三类 mock 用例，检查引用、澄清、拒绝与执行路径。
