# D047｜Chunking 与信息边界

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M05 · 前置：D007、D046

## 预习：问题与知识地图

切块在检索粒度、信息完整性和上下文预算之间取舍。固定 token 数便于控制规模，结构感知切块可保留标题/段落等关系；overlap、父子块和元数据能缓解边界损失，但也增加重复和成本。

## 核心框架与案例

本次文本：“员工可以申请报销。仅限经批准的出差，个人旅游不适用。”若只检索到第一句，答案可能丢失限定条件。切块质量不能仅看长度是否均匀，要看问题所需证据是否一起保留或能被重新关联。

较大 chunk 可能包含完整条件，却引入噪声和更高 token 成本；较小 chunk 容易精准匹配局部词，却可能缺背景。Overlap 增加边界覆盖，也可能让 Top-K 中多数候选是重复内容，浪费有效证据预算。

比较时固定语料、模型、查询集和检索策略，只改变切块方式；同时检查出处映射和删除更新粒度。

## 易错边界

不存在从本计划即可推出的通用最佳 chunk 长度。按字符数切割不等于按 tokenizer 的 token 数。文档里的否定、单位、时间和表头常是关键条件，不能因“不像正文”而丢弃。
