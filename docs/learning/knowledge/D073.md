# D073｜协议与执行边界门槛

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M07 · 前置：D068–D072

## 预习：复习地图

从一条 MCP 请求到隔离执行，逐层问：谁发起？参数是什么？有权吗？批准有效吗？在哪执行？允许访问什么？怎么停止？结果与资源怎样处理？每个问题必须有负责组件与可信证据。

## 核心框架与案例

本次边界例：一个已认证用户调用工具读取不属于自己的 artifact。连接认证通过、schema 合法和 Sandbox 可访问路径，都不能替代业务对象授权。应由明确策略拒绝，而不是等模型自我判断。

取消与资源超限是另两类测试：取消后查看远端实际执行状态，超限后查看进程、文件与计费/预算记录。审计应记录决定与结果，但脱敏秘密和不必要内容。

## 易错边界

协议合规不是全系统安全认证。Mock 可以证明代码按某状态拒绝请求，但不能冒充真实 microVM 安全评估。测试只覆盖所构造的边界，未测部分要保留风险说明。

## 复习：先独立回答

1. 用户认证成功但对象不属于它，哪一层应拒绝，依据是什么？
2. 为什么“工具请求已取消”还不是完整清理证据？

<details><summary>展开核对要点</summary>

业务授权层根据可信身份、租户与对象策略拒绝；不是仅看网络会话。需要检查实际动作是否终止、子进程和临时资源是否回收、已发生副作用如何处理。

</details>

## 动手与达标证据

演示一条完整调用链，注入无权访问、取消和资源超限；交版本、身份/策略说明、结果与清理记录。完整讲义的实际结果在真正运行后填写。
