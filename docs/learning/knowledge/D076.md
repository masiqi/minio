# D076｜Agent Outcome、Trajectory 与回归套件

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M08 · 前置：D074、D075

## 预习：问题与知识地图

Agent 验收同时看任务完成、约束遵守与执行代价。Outcome 是结果；trajectory 是行动轨迹；二者不是二选一。允许不同合法路径，仍要检查必要审批、安全和预算条件。

## 核心框架与案例

本次例：目标是创建一个正确工单。路径 A 查询一次后创建，路径 B 先补查再创建；若都满足证据、审批和预算，可以都是合法解。反过来，最终工单正确但未经授权，不能因 outcome 表面成功而通过。

Capability 集用于探索尚未掌握的任务；regression suite 用于保护已有行为，两者可重叠但目的不同。所有回归题满分不证明未知任务也会成功。

每个 trial 应重置必要环境，记录缓存策略、文件和数据库初始状态。多次中至少成功一次与每次都成功代表不同可靠性要求，不应混报一个“成功率”。

## 易错边界

将唯一工具顺序写死可能误判合法方案；完全不看过程又可能漏掉越权和超预算。重复试验数、采样设置和任务分布必须明示，不能从几次成功推广无限可靠。
