# D069｜Transport、身份、授权与凭证边界

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M07 · 前置：D060、D068

## 预习：四层分别回答什么

Transport 回答如何传消息；认证回答对方是谁；授权回答该主体能做什么；批准回答特定风险动作是否得到必要确认。不能把网络连通、token 有效、业务有权和本次批准混为一谈。

## 核心框架与案例

本次调用链：用户 → host → MCP server → 下游数据服务。逐跳标明谁代表谁、凭证由谁持有、适用的 audience/scope、何时过期、日志是否脱敏，以及最终在哪层判定文档访问权。

一个用于 server A 的 token 不应被任意转发给 B；即使连接已认证，业务对象仍可能不属于当前用户或租户。不同 transport 和部署的认证机制可能不同，不能把某版 HTTP 授权流程直接套到所有本地进程连接。

模型上下文不应包含不必要的底层 secret；模型可提议资源，可信身份与凭证由应用层管理。

## 易错边界

Scope 不是所有业务对象权限的完整替代。日志可观测不代表可以记录完整凭证。成功刷新 token 不等于原用户对业务动作的批准仍有效。

## 复习：先独立回答

1. 用户已登录，为什么仍可能被 server 拒绝某个 tool？
2. 为什么不能为了调用方便，把 host 所有凭证都给模型或下游？

<details><summary>展开核对要点</summary>

工具或对象可能超出 scope、业务权限、租户范围或批准条件。无限传递凭证扩大泄漏和越权面，应按信任边界最小化，并核验每个接收方与用途。

</details>
