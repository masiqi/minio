# D072｜Sandbox 威胁模型与资源生命周期

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M07 · 前置：D060、D063、D071

## 预习：问题与知识地图

先明确不可信代码可能触及哪些资产，再决定隔离方式。边界包括文件、进程、网络、身份、secret，以及 CPU、内存、时间、磁盘和输出额度。Sandbox 是一组受配置与宿主环境约束的机制，不是绝对安全标签。

## 核心框架与案例

本次教学执行器只允许读取任务目录、生成报告文件，不允许任意外连。设计时需要区分输入挂载、临时工作目录、最终 artifact、凭证注入和回收。执行结束不代表文件已清理；artifact 被保留也要有租户权限与保留期限。

容器与 microVM 可提供不同隔离/启动/资源/运维取舍，应结合威胁模型选择。不能仅凭名称决定安全等级；配置、共享内核或虚拟化边界、网络规则与宿主维护都影响实际风险。

## 易错边界

只限制 CPU 不能阻止读敏感文件或外传数据。只设 timeout 不保证子进程、网络连接和临时文件都回收。测试几个拒绝用例不等于证明没有任何逃逸路径。

## 复习：先独立回答

1. 一段代码运行只花1秒，为什么仍可能有安全风险？
2. 临时文件和最终 artifact 的生命周期应该完全相同吗？

<details><summary>展开核对要点</summary>

它仍可能越权读取、写入或传出数据，速度不决定权限。临时资源一般随任务清理，保留 artifact 需独立授权、归属、审计与删除规则。

</details>

## 动手与达标证据

仅在受控本地或模拟环境验证只读路径、网络白名单、资源上限、取消和清理；不做真实逃逸攻击，不执行生产未知代码。标明实测与设计边界。
