# D065｜Planning、Reflection 与 Multi-Agent 的边界

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M06 · 前置：D061–D064

## 预习：三个增加复杂度的选择

Planning 把目标分成带依赖的步骤；Reflection 对结果作检查并决定是否修正；Multi-Agent 把部分工作交给多个角色或执行单元。它们都应相对简单 workflow/单 Agent 基线证明收益，而不是作为“更智能”的装饰。

## 核心框架与案例

本次阅读任务：一方提取证据，另一方整理答案。分工可能允许并行或不同工具权限；也可能重复检索、丢失交接条件或一起相信错误证据。需要明确输入/输出契约、共享状态、冲突解决、总预算与退出条件。

反思若没有新证据，只让同一模型再评价一次自己，可能巩固错误或把正确答案改错。检查应尽量连接可观察结果、代码断言或原始证据；不需要保存或索取模型私有思维过程作为质量证明。

计划也是可修订状态，不是执行前生成一段长文字就永久正确。环境反馈、用户改需求和工具不可用都可能改变下一步。

## 易错边界

多个名字不保证错误独立；两个 Agent 同意不等于事实已验证。更长的轨迹不等于更深入。并行省时的收益可能被协调、重复工作与预算放大抵消。

## 复习：先独立回答

1. 怎样判断一个任务值得分工，而不是多加一次模型调用？
2. 反思让结果变差，应保留还是隐藏这个实验？

<details><summary>展开核对要点</summary>

识别可分解瓶颈、权限/能力差异或并行机会，并在同一成功标准下比较质量、成本和延迟。必须保留负结果，它正是决定删减复杂度的证据。

</details>
