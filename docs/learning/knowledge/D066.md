# D066｜框架映射与同任务对照

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M06 · 前置：D061–D065

## 预习：问题与知识地图

理解机制后再选择框架，目标是判断哪些基础设施值得复用、哪些正确性仍由业务负责。映射对象包括模型接口、工具契约、状态、checkpoint、审批、恢复、预算、可观测性和部署边界。

## 核心框架与案例

本次迁移策略：只把 P3 的一条已可测试流程放进一个候选框架，不立即重写整个系统。保持 fake/model、工具、数据、成功标准和故障测试相同，比较行为与工程成本。

框架保存节点结果，可能帮助恢复；但外部工单已写入、确认未存的窗口，仍依赖业务幂等与协调。模型路由更易写，也不代替权限校验。用契约检查抽象，而不是只数节省了几行代码。

候选选择需在实施时核验官方文档、版本、维护状态、许可和部署约束。本框架不指定永远最优的产品，也不要求同时背多个 SDK。

## 易错边界

框架能跑示例不证明适配真实需求。API 名称类似不保证持久化、取消、重试语义一致。一次迁移不应悄悄改变业务成功标准。
