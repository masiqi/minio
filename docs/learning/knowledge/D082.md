# D082｜垂直集成：检索、模型、工具与持久状态

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M09 · 前置：[D081](D081.md)

## 预习：问题与知识地图

组件各自通过不保证组合后边界正确。集成链：用户任务与身份 → P2 检索工具 → Context → P3 模型决策 → 参数/授权/批准 → 执行 → 状态持久化 → 业务结果核验。每条边都需要传递正确身份、版本和错误语义。

## 核心框架与案例

本次场景：模型从资料中找到“需要提交工单”，但这只是事实或流程描述，不是用户授权创建工单。集成层必须将证据通道和批准通道分开，避免“读到一句话”直接变成执行许可。

先用 deterministic fake 和 mock 写工具固定行为，验证控制流、取消和恢复，再在明确预算和数据授权下替换真实模型做质量对照。Fake 的可重复成功只证明所测控制逻辑，不证明真实模型判断质量。

Correlation ID、任务身份、索引版本与工具调用标识贯通各组件，有助于从最终错误追到责任层。一个组件超时后，要明确全链路继续、终止还是恢复。

## 易错边界

接口字段名相同不代表语义一致。子组件返回空数组，可能是无结果、无权限或超时，不能在集成时抹平。事后补一段 prompt 不能代替修复错误的状态传递。

## 复习：先独立回答

1. 所有单元测试都通过，端到端为何仍可能失败？
2. 将 fake 换成真实模型后，哪部分需要重新验证？

<details><summary>展开核对要点</summary>

接口语义、身份传播、版本、失败与取消组合可能有缺口。除了保持契约测试，还需真实任务质量、工具建议、拒答和资源表现；不能直接继承 fake 的质量结论。

</details>
