# D044｜模型应用选型门槛与缓冲

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M04 · 前置：D037–D043

## 预习：选型地图

不要从工具名称开始，而从故障开始：输入表达不清？输出格式不稳定？知识缺失或过期？任务行为需要改变？延迟、成本或数据边界不满足？这些问题对应不同证据和手段，不能统称“模型不够强”。

## 核心框架与案例

本次任务：依据每日更新的内部政策，输出固定字段的合规工单建议。可先比较明确 prompt/schema 与检索证据；若行为模式持续不满足且有合格训练数据，再评估 SFT/LoRA；涉及写操作仍由授权与执行器负责，不由微调代替。

决策记录至少有目标、约束、当前基线、候选方案、同条件测试、风险和回退。知识新鲜度、格式正确、事实支持、业务授权和服务可用性各自验收，不以某个总分覆盖全部。

## 易错边界

“微调能解决一切”“RAG 永远不用训练”“便宜模型一定更划算”都不是证据。模型或 SDK 变化可能影响角色、schema、工具与流式契约，不能只换配置不重跑测试。

## 复习：先独立回答

1. 新政策每天更新，为什么不应未经比较就决定每天重新微调？
2. 方案格式合格但引用不受支持，应在哪类指标上失败？

<details><summary>展开核对要点</summary>

需比较数据时效、更新成本、可删除性、引用能力与训练收益，检索是可测试的候选。格式与证据支持是不同指标，不能因 schema 通过忽略事实问题。

</details>

## 动手与达标证据

提交 Prompt/RAG/SFT/LoRA 选型 ADR，列出假设、测量计划、失败与回退；演示格式错误及超时处理。未测性能只写假设。
