# D055｜GraphRAG / LightRAG 的数据流与成本

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M05 · 前置：D046、D054

## 预习：问题与知识地图

图方案增加实体和关系等表示，目的是让部分跨片段关联问题更易检索；它不天然替代普通 RAG。知识链：文本片段 → 抽取实体/关系 → 合并及出处 → 图/向量检索 → 原始证据组装 → 答案验证。

## 核心框架与案例

本次阅读场景：不同章节分别描述人物、组织和事件，问题需要连接三处证据。图结构可能帮助发现关联入口；但实体同名、关系抽错或来源丢失，会使错误在后续检索中被放大。

“图上 A→B→C 有路径”不等于“原文证明了问题要求的因果关系”。需要核对每条边的定义、来源、时间和推断方式。把模型抽取内容当作待核验表示，而不是自动升级为事实数据库。

LightRAG 的具体入库与查询流程要读取固定版本的官方实现；本文不把所有 GraphRAG 系统说成一种算法，也没有审查用户未提供的私有阅读系统源码。

## 易错边界

新增表示同时增加抽取、合并、索引、更新删除和运维成本。简单事实查询未必需要图。图更复杂不是成绩，能说明何时不采用也是能力。
