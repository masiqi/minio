# D068｜MCP 的架构与协议边界

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M07 · 前置：D059、D067

## 预习：问题与知识地图

MCP 标准化模型应用与外部能力/资料的交互，减少每次独立适配。Host 是组织交互的应用，client 负责协议连接，server 提供相应能力。协议层不是模型本体，也不自动成为有业务权限的 Agent。

## 核心框架与案例

本次场景：阅读助手作为 host，通过 client 连接文档 server，发现只读检索工具，再发起调用。Server 返回结果后，host/runtime 仍需处理状态、错误、上下文与任务是否完成。

Tools、resources、prompts 是不同原语：可调用能力、可读取资料以及提示模板等有各自契约；具体控制与发现流程按选定规范版本核对。初始化与能力协商用于确定双方支持什么，不是对用户全部操作的无限授权。

## 易错边界

工具被发现不表示当前用户有权使用。MCP server 不必与 Sandbox 同进程，也不必承载整个 Agent loop。协议标准化不替代业务数据模型、批准、幂等或限额。

## 复习：先独立回答

1. 普通检索函数接上 MCP 后，哪些业务职责仍然保留？
2. 为什么“用了 MCP”不能回答“用户是否有权读取文档”？

<details><summary>展开核对要点</summary>

数据授权、输入业务校验、结果语义、资源限制和错误恢复仍需实现。协议描述通信和能力，具体主体对对象的权限来自适用身份与策略检查。

</details>
