# D007｜文本、Tokenizer、词表与 Token ID

[目录](README.md) · [原教学卡](../daily/D001-D030-foundations-training.md) · M01 · 前置：[D002](D002.md)、[D005](D005.md)

## 预习：问题与知识地图

原始文本不能直接进行矩阵乘法。Tokenizer 按特定规则把文本转换为 token 序列，词表把 token 对应到整数 ID，Embedding 再将 ID 变成向量。一个 token 不固定等于一个中文字符、英文词或字节。

## 核心框架与例子

本次教学词表假设：“苹果”→2，“很好”→7，“吃”→9。若教学规则这样分词，句子得到 [2,7,9]；这不是任何生产 tokenizer 的实际输出。ID 只是查表地址：7 大于 2 不代表更重要、更接近语义或有七个维度。

需要一起保存 tokenizer 规则、vocabulary、特殊 token 和模型版本。encode/decode 的行为还可能涉及空格、规范化和特殊符号，不能对所有实现都承诺原始字节完全可逆。BPE 等子词方法的动机是平衡词表大小与可组合性，不必在本课背完整训练算法。

## 易错边界

两个模型的 ID=42 可能不是同一个 token。换 tokenizer 后保留原 embedding 行号直接使用，可能让每个 ID 查错向量。按字符数估算精确 token 预算也可能出错。

ID 是离散索引，没有语义距离定义。必须按 token 对应关系重排或重新构建权重及相关输出映射；不能只因词表大小没变就直接兼容。
