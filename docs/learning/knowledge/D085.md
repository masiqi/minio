# D085｜质量、成本、延迟与消融比较

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M09 · 前置：D075、D076、D084

## 预习：问题与知识地图

消融通过有控制地移除或改变一个因素，判断它对系统有什么贡献。选择图检索、rerank、reflection 或 multi-agent 中的一项，固定其他设置，联合比较质量、资源和失败边界。

## 核心框架与案例

本次教学情境（不是实测结论）：加入反思后，一部分复杂题改善，简单题更慢且偶尔被改错。结论不能只写“反思有效/无效”；需要按题型、成功率、成本、尾延迟与风险解释，也可能设计只对特定失败触发。

报告保留原始 trials、任务集版本、样本数、重复次数、seed/模型配置、输入输出长度和费用口径。多项同时变化时只能报告联合变化，不能把收益全归给某一组件。

## 易错边界

小样本略高可能是波动；挑选成功案例会夸大收益。安全测试失败不能被平均质量提升抵消。复杂度本身有维护、排错和可靠性成本，不只是调用费用。

## 复习：先独立回答

1. 为什么一次比较中不宜同时换模型、prompt 和检索方案后只归因于检索？
2. 哪些情况下删掉一个组件反而是更好的工程结果？

<details><summary>展开核对要点</summary>

无法分离各因素作用和交互。组件没有可靠收益、放大成本/错误/耦合，且简单方案满足目标时，删减可以提升可维护性与可靠性。

</details>
