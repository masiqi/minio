# D041｜推理性能：测量、量化与 Attention 优化

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M04 · 前置：D039、D040

## 预习：问题与知识地图

优化从测量开始，而不是先选一个流行技术。需要区分首 token 延迟 TTFT、后续每 token 延迟、吞吐、总响应时间和峰值内存；再判断瓶颈位于计算、内存访问、排队调度还是外部工具。

## 核心框架与例子

本次教学对照：方案 A 每秒输出100个 token，B 输出200个；若 A 的并发为1、B为16，不能据此说单请求加速2倍。要固定模型、输入/输出长度、batch、并发、精度、设备、预热和测量范围，并报告尾延迟。

量化用更低精度表示部分权重或激活，可能减少存储与带宽，但质量、实际 kernel 支持和转换开销需要测。FlashAttention 优化精确 Attention 的访存与中间量组织，避免朴素实现完整物化大矩阵的开销；不是把所有密集位置对计算自动变成线性。

KV Cache 减少自回归重算，batching 提高资源利用，但也可能增加排队或缓存需求。优化手段针对不同成本，不能互相当同义词。

## 易错边界

N×N 关系存在不意味着所有实现都必须完整保存一个 N×N 矩阵。降低 bit 数不保证端到端延迟按相同比例下降。CPU 正确性实验不能冒充 GPU 性能评测。
