# D067｜P3 初版门槛：可靠执行，而非只跑通 Demo

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M06 · 前置：D058–D066

## 预习：复习地图

P3 初版应能说明正常、拒绝、失败和恢复路径。链路：任务输入 → 模型建议 → tool contract → 身份/审批 → 执行 → 幂等与持久状态 → 结果核验 → 预算内停止。没有使用框架不影响门槛，只看实现与证据。

## 核心框架与案例

本次复习用一张事件时间线：工具请求提出、参数通过、批准有效、执行发出、结果未知、查询确认、任务结束。每个事件都应关联任务和业务对象，让另一人能解释为何没有重复写入、为何还需要或不需要继续。

模型文字、trace 和环境 outcome 各有作用：文字是建议/表达，trace 是过程，环境状态是任务结果的一部分。它们不应互相冒充。

## 易错边界

成功 Demo 不能证明非法请求被拒绝。一次恢复测试通过不能保证所有外部服务 exactly-once。没有实际运行的安全或恢复项，必须标为设计/待验证，不能靠文档漂亮补足。

## 复习：先独立回答

1. 模型说工单已建，但后端没有记录，应按什么判断任务成功？
2. 哪些失败测试最能区分“会调用工具”和“有可靠 runtime”？

<details><summary>展开核对要点</summary>

按明确业务成功条件与可信环境状态核验，不能以模型自述作证。未批准、参数非法、成功后丢响应、中断恢复、取消和预算耗尽等能暴露关键边界。

</details>

## 动手与达标证据

按原卡演示工具成功、非法参数、未批准、超时、重复、中断恢复和预算耗尽；交付运行入口、loop、契约、测试与故障分析。正式验收更换一个失败条件，不照本卡背答案。
