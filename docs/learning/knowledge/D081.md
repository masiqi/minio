# D081｜综合项目范围、业务成功与验收合同

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M09 · 前置：P2、P3 与 M08 阶段证据

## 预习：问题与知识地图

综合项目复用已有 RAG 与 Agent，而不是重新起一套重复代码。先写清用户、目标、非目标、允许数据与动作、成本约束和验收；再选一条能贯通的垂直流程。Demo 和生产就绪是不同交付级别。

## 核心框架与案例

本次项目示例：“依据授权文档回答问题，在用户确认后生成 mock 工单”。成功不仅是有回答，还要引用正确、拒绝无权限数据、批准绑定参数、实际工单结果可验证、预算可控。

需求—测试追踪表将每条要求关联到证据。例如“删除后不再引用”对应索引/缓存失效测试；“未经批准不写入”对应执行器拒绝测试；“问题无答案时说明不足”对应无答案题集。范围外功能明确不承诺。

Charter 说明要交付什么，架构说明怎样实现，测试说明哪些承诺已验证。三者要一致，不能文档写得比实际系统强。

## 易错边界

集成越多组件不等于项目越完整。已完成的 P1 是机制实验，不要求用 tiny LM 直接支撑高质量生产回答。无需未经授权引入真实客户资料或生产写操作来证明能力。

## 复习：先独立回答

1. 为什么必须写非目标，而不只列想做的功能？
2. 某项关键权限测试失败，能否因为核心 Demo 成功而宣称交付完成？

<details><summary>展开核对要点</summary>

非目标限定工作和验收边界，防止用模糊范围承诺未实现能力。关键约束失败应明确阻断或标为未完成，不能被展示成功掩盖。

</details>
