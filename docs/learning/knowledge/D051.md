# D051｜Context 构建、压缩、引用与拒答

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M05 · 前置：D037、D050

## 预习：问题与知识地图

检索到证据并不等于模型已经有效使用。Context Builder 需要选择、去重、排序、控制 token 预算，附带来源与边界，再检查答案是否受证据支持。资料不足或冲突时，也需要明确产品行为。

## 核心框架与案例

本次例：原文“本服务支持退款，但定制商品除外，申请须在7日内”。若压缩成“支持退款”，就丢掉对象与时间限制。压缩目标不是最短，而是在预算内保留回答所必需的条件、否定、时间和来源。

一个引用应能从答案中的主张定位到具体文档版本与原文片段。答案后挂一个文件名，不说明该文件支持每句话。模型生成后可检查引用存在性、位置及主张支持；这些检查的自动化程度由任务决定。

证据冲突时可分别说明出处与条件，或请求澄清；无授权证据时不能用生成流畅的猜测填空。长窗口增加可装入内容，不保证所有内容都被可靠利用。

## 易错边界

把所有候选塞进 prompt 可能放大重复和矛盾。摘要是派生内容，不应失去可回溯原文。引用合法与主张正确不是同一检查。

2. 怎样检查“压缩没有丢掉关键条件”？
