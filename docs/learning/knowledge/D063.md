# D063｜Checkpoint、恢复与持久化执行

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M06 · 前置：D061、D062

## 预习：问题与知识地图

持久化执行需要知道“最后确定完成了什么”和“什么结果还不确定”。Checkpoint 不能只存自然语言聊天，还应保存任务身份、待执行动作、批准、幂等键、已确认结果、预算和必要版本。

## 核心框架与案例

本次三种崩溃窗口：执行工具前退出；工具完成但结果记录前退出；结果持久化后退出。第一种可能安全发起尚未发生的动作；第二种需查询/协调已发生副作用，不能盲重放；第三种应复用已确认结果继续。

Resume 是从可解释状态恢复；Replay 是重新推进某些步骤，两者都要考虑外部动作是否可重试。状态 schema 变化也需要迁移或拒绝策略；旧 checkpoint 不应被新代码静默误读。

身份、批准和参数绑定在恢复后仍有效才允许执行；权限可能已撤销，过期批准也不能因“以前批准过”无限有效。

## 易错边界

框架能恢复 Python 流程不代表外部系统的事务自动一致。保存 messages 不足以区分工具未执行与成功后丢响应。恢复预算若重置为初始值，会绕过总任务限额。
