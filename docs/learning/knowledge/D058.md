# D058｜Workflow、LLM+Tools 与 Agent 的控制流

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M06 · 前置：D037；仅接检索工具时额外依赖 P2

## 预习：问题与知识地图

区分由程序预先规定步骤的 workflow，与允许模型根据反馈选择下一步的 Agent。LLM 返回工具请求只是建议；真正执行由 runtime 完成，再把环境结果回给模型。Agent 不等于模型拥有操作系统权限。

## 核心框架与案例

本次任务是“查询订单状态并在必要时提出工单建议”。固定 workflow 可先查订单再按规则分支；Agent 可根据返回结果决定是否查询更多信息。两者都需要工具契约、身份、状态、预算和终止条件，不因为步骤由模型选就豁免工程约束。

核心循环：当前目标/状态 → 模型提议 → 验证与授权 → 工具执行 → 环境结果 → 状态更新 → 继续/停止。成功标准应来自环境结果，例如工单实际存在，而不是模型说“完成了”。

## 易错边界

只有一次工具调用也不自动说明是复杂 Agent；固定流程里可以使用 LLM。多 Agent 不保证更好。构建不含检索的 Agent 不要求先训练模型或完成 RAG，本课顺序是本项目的教学安排。
