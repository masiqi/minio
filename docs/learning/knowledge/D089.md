# D089｜RAG、Agent 与企业系统设计面试

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M10 · 前置：P2、P3、M07、M08

## 预习：系统设计的回答框架

先澄清目标、用户、规模、数据与动作权限；再给最小可行方案、关键数据/控制流、评测、故障与成本；最后解释替代方案和取舍。面试一次一个问题，先完整回答再追问，不预先泄露标准答案。

## 核心框架与案例

本次准备场景是“企业文档问答并执行受控任务”。先问哪些任务要读数据、哪些要写状态；证据从哪来、何时更新删除、哪些租户可见；然后决定固定 workflow、Agent、检索和持久状态的边界。

需要清晰区分：RAG 提供外部证据，Memory 管理持久信息策略；workflow 与 Agent 的控制权不同；MCP 是协议层，runtime 管执行过程；Observability 记录运行线索，Evaluation 判断任务质量。不要用一套框架名字回答所有职责。

遇到新约束，说明哪些假设被改变、最小改动与验证，不强行给“标准架构”。实际项目证据比术语数量更重要。

## 易错边界

先画复杂图再询问需求，容易答非所问。用模型自评替代业务结果、用 prompt 代替 IAM、用 checkpoint 代替幂等，都是层次混淆。未测的容量和安全结论不能说成事实。

2. 面试给出信息不足时，怎样既不胡猜又能推进设计？
