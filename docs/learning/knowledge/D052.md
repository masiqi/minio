# D052｜Context、Conversation History 与 Memory

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M05 · 前置：[D051](D051.md)

## 预习：问题与知识地图

Context 是某次模型调用实际读取的内容；Conversation History 是保存的对话记录；Memory 是按策略写入、更新、检索与删除的持久信息。保存历史不等于每次全量读入，写入 Memory 也不等于更新模型权重。

## 核心框架与案例

本次记忆记录示例：subject、fact、source、observed_at、scope、expiry、status。字段是教学方案，不是统一标准。用户说“我的地址变了”时，不应只新增一条无版本事实；应识别主体与时间，处理旧事实冲突，并在检索时选择有效且获授权的信息。

先区分任务工作状态、事件记录、稳定事实和模型推测。它们的写入门槛不同。长期事实需要来源与可修正路径；“模型猜用户喜欢某物”不能自动升级为可靠个人事实。

读流程关注相关性、时效与权限；删流程关注原记录和派生索引、摘要、缓存是否还保留。当前窗口清空并不证明所有持久副本已删除。

## 易错边界

更多记忆可能引入过期事实与隐私风险。TTL 不代替明确撤权与删除。把所有工具日志塞入下一次 Context，不是完善的 Memory 系统。

## 复习：先独立回答

1. 用户纠正旧事实后，写入与读取两侧分别要做什么？
2. 模型参数、长期 Memory 和本次 Context 的更新机制有何不同？

<details><summary>展开核对要点</summary>

写入需版本/冲突处理与出处，读取需过滤过期或被替代的信息。参数通常经训练更新；Memory 经应用存储策略更新；Context 由每次调用的构建逻辑选择。

</details>
