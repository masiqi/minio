# D008｜Embedding 查表与 Contextual Representation

[目录](README.md) · [原教学卡](../daily/D001-D030-foundations-training.md) · M01 · 前置：[D007](D007.md)、[D003](D003.md)

## 预习：问题与知识地图

Representation 是供后续计算使用的数值表示；本课讨论向量形式，不把每一维都当成人工标注的语义标签。链路：token ID → embedding lookup → 加入位置与上下文处理 → hidden representation；检索整段文本的 embedding 又有不同训练目标与汇聚方法。

## 核心框架与例子

本次示例：词表 4 项、每项 3 维，参数表 E 为 4×3。IDs=[2,0,2] 查出 E[2]、E[0]、E[2]，得到 3×3。两次 ID=2 的初始查表结果相同；经过不同位置或可见上下文的计算后，表示可能不同。

模型不是先把一个坐标命名为“水果”，再人工填数。语义通常分布在多维组合中；向量大小和方向只是几何描述，能否支持任务要看训练与后续运算。参数表会如何学习留到 M02，本课先分清数据流。

## 易错边界

Embedding 数值没有通用的 [-1,1] 限制。输入不同也不保证任意网络输出必不同。单 token 的初始向量不等于整篇文档的高质量检索向量；后者不能只靠选择一行来保证。

## 复习：先独立回答

1. 同一个 token 在同一参数表里查两次，什么一定相同，什么后续可能不同？
2. 词表变大与表示维度变大，分别改变 E 的哪一轴？

<details><summary>展开核对要点</summary>

相同 ID 的 lookup 行相同；位置处理与上下文更新结果可能不同。词表大小改变行数，表示宽度改变列数；这两种变化不要与句子 token 数混淆。

</details>
