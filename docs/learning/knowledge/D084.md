# D084｜故障注入、恢复与预算约束

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M09 · 前置：D063、D078、D082

## 预习：问题与知识地图

架构承诺要在失败条件下验证。按模型、检索、工具、状态存储分别列出失败，再选择提交窗口注入；观察恢复、补偿、拒绝、预算与最终环境状态。所有测试限定在授权、隔离和可控环境。

## 核心框架与案例

沿原卡五类模拟：进程重启；工具已写但响应丢失；凭证撤销；provider 限流；预算耗尽。每类先写预期，再记录实际，不在结果出来后改成功标准。

本次重点例：写成功后响应丢失，恢复程序读取 pending 状态。如果立即重新创建，可能重复；应使用稳定幂等键、查询外部结果或明确的协调策略。测试既看“最后任务成功”，也看写入次数与预算是否超限。

撤权测试要检查恢复时是否重新取得当前有效权限；限流测试要检查是否形成重试风暴。不同故障的恢复动作不应机械相同。

## 易错边界

模拟成功只支持本环境和所测契约，不证明任意第三方服务 exactly-once。成功取消不自动说明已发生副作用被撤销。故障注入不是对生产或外部服务施压的许可。
