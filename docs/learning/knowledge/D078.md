# D078｜Model Gateway、SLO、预算与降级

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M08 · 前置：D039、D041、D062、D076

## 预习：问题与知识地图

Gateway 不只是转发 API。它协调 provider 契约、限流、超时、熔断、路由、fallback、质量门槛和预算。SLO 定义目标服务水平，应区分请求完成、任务成功、首 token、总耗时和尾延迟。

## 核心框架与案例

本次场景：主模型超时，备用模型便宜但不支持某工具 schema。盲目 fallback 可能返回不兼容请求；正确设计要在路由前检查能力、数据边界与预算，必要时降级为只读解释或明确失败，而非伪装同等服务。

重试、排队和 provider 调用都消耗总 deadline；无限重试会放大故障与费用。熔断减少持续向明显失败的依赖发送请求，但何时开启、恢复与探测需要明确策略。

成本测试先用 fake 价格与计数器证明逻辑，真实费用另查实际计费规则。平均延迟和 p95 等尾部指标共同帮助理解体验。

## 易错边界

便宜单次调用不等于更低任务成本，可能需要更多尝试。服务 HTTP 成功不保证业务质量。fallback 不能悄悄改变隐私、权限或副作用要求。

2. 一个任务重试3次，预算应该每次重置还是总量累计？

<details><summary>展开核对要点</summary>

不同模型可能不支持相同结构、工具或数据处理条件。总预算应按任务政策累计并限制，不能靠重试获取无限额度；具体预留与结算需设计。

</details>
