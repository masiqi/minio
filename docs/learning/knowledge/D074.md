# D074｜Testing、Observability 与 Evaluation

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M08 · 前置：D054、D067

## 预习：问题与知识地图

Testing 检查特定程序行为；Observability 帮助看见和诊断运行过程；Evaluation 判断系统在任务集上是否达到目标。三者相关，但“每个调用都成功”不等于“用户任务成功”。

## 核心框架与案例

一个 task 定义任务与环境；trial 是一次尝试；trace 记录执行轨迹；outcome 是实际结果；grader 按标准判断。定义可能因工具而略有不同，本课程要保持自己的 schema 一致。

本次例：要求“仅创建一个工单”。单测验证 schema 校验；trace 显示两次创建调用都返回成功；outcome 却是两个工单，因此任务失败。只看 HTTP 状态或模型最后一句话会漏掉业务错误。

评测记录初始环境、任务约束、允许动作、最终状态，以及模型、prompt、工具、数据和配置版本。先定义成功标准，再选择如何观察它。

## 易错边界

大量日志不等于有质量评价。最终文本评分不能代替数据库状态检查。一个工具报错也不一定意味着任务最终失败，系统可能在预算内正确恢复；过程与结果要一起解释。
