# D064｜Context Router、记忆与执行预算

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M06 · 前置：D051、D052、D061

## 预习：问题与知识地图

业务 Context Router 决定本步模型需要哪些目标、状态、历史、证据与工具结果；它不是模型内部的 Attention。预算控制则决定系统还允许花多少步骤、token、时间和费用，不能由模型自说自话。

## 核心框架与案例

本次任务原始约束是“只读，不创建工单”。长历史被摘要后若这条约束消失，模型可能提出写操作；正确系统仍应在 runtime 策略层拒绝，但 Context Builder 也应有约束保留测试，而不是完全依赖最后一层兜底。

组装流程：读取可信任务状态 → 选择相关且获授权的记忆/证据 → 截断或压缩大结果 → 保留来源与关键约束 → 计算预算 → 调用或降级。批准记录、未完成事项和结果未知状态不能被“总结一下”随意改写。

本地测试可用 fake 价格与计数器验证预算扣减，但它是测试数值，不是实际账单。真实模型成本口径、缓存计费等需要单独核验。

## 易错边界

窗口越大不代表应把所有历史读入。先调用再检查预算会带来越限窗口。模型说“再一步就完成”不是授权增加预算的依据。

2. 长工具返回超出预算，怎样避免直接丢掉关键证据？
