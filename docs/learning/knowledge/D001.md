# D001｜起点校准与可复现实验环境

[目录与使用方法](README.md) · [原教学卡](../daily/D001-D030-foundations-training.md) · M00

## 预习：问题与知识地图

**沿用原卡：** 使用已有 Baseline，只检查未验证的 Python/PyTorch 与实验条件，不重做全套能力测试。前置是能够阅读和运行一个小脚本，不要求会训练网络。

本单元解决“同样的代码为何得不到可比较的结果”。知识链：输入与数据版本 → 代码与配置 → 依赖/设备 → 随机性 → 输出与日志 → 重跑证据。把后端的故障复现经验迁移过来，但不要把环境问题误判成模型机制问题。

## 核心框架与例子

以下为本次教学展开：一份实验记录至少能回答“谁运行、什么代码、什么数据、哪些配置、在哪种环境、得到什么结果”。例如同一张量运算的两次运行，记录 Python/框架版本、CPU/GPU、dtype、seed、输入摘要和输出；相同 seed 并不保证跨设备、跨版本逐位相同。

区分三类物件：输入数据是这次算什么；模型参数决定怎么算；实验配置控制如何运行。先用 CPU 和合成数据验证机制，真实模型调用与付费训练不是入门前提。

## 易错边界

能 import 库只说明环境的一部分可用；一次跑通不是可复现。日志不要保存密钥或未经授权的正文。此处不要求搭建大型 MLOps 平台。

## 复习：先合上正文回答

1. 两次结果不同，你会优先核对哪几类信息，而不是马上改网络？
2. 只交一个 seed，为什么别人仍可能无法复现？

<details><summary>展开核对要点</summary>

核对输入/划分、代码、配置、依赖、设备/精度与随机操作。seed 只约束部分随机过程，不包含整个环境和执行语义；复现还应定义数值容差与比较对象。

</details>
