# D037｜模型接口、Prompt 与 Structured Output

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M04 · 前置：D031、D036

## 预习：问题与知识地图

应用不能把模型当作总能按要求返回的普通函数。调用契约包括输入角色/数据边界、输出结构、错误、拒答、超时、流式生命周期及调用方处理。Prompt 改动通常改变输入，不是训练更新模型权重。

## 核心框架与例子

本次接口示例：请求返回一个工单建议，字段包含 title、reason、evidence_ids。即使结果是合法 JSON，title 也可能空白，evidence_ids 也可能不存在；schema 校验、业务校验和证据校验应分开。模型返回“已创建”只是文本，是否写入要由执行器和实际存储结果证明。

设计可替换 adapter，让业务层只依赖自定义请求/响应契约；用 deterministic fake 测试固定行为。真实 provider 的角色支持、schema 子集、拒答格式、工具能力和多模态输入要依当前文档核验，不用一个接口假设所有模型一致。

## 易错边界

Structured Output 降低格式处理难度，不自动保证事实、权限和操作成功。客户端完成接收不是业务完成。流式中断后的部分 JSON 不能当作完整可执行命令。

2. 为什么调用方需要显式区分拒答、空结果、错误和成功？

需校验业务规则、数据真实性、证据、身份授权及副作用结果。四类状态对应不同产品行为和恢复策略，混成空字符串会隐藏失败甚至触发错误执行。
