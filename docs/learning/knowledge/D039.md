# D039｜Prefill、Decode 与 KV Cache

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M04 · 前置：D010、D035

## 预习：问题与知识地图

自回归生成每次扩展前缀，重复计算所有旧位置很浪费。Prefill 处理已有前缀；Decode 处理新增 token；KV Cache 保存可复用的各层 Key/Value 中间表示。它不同于聊天文本、长期 Memory 或模型参数。

## 核心框架与例子

在固定参数、因果结构和一致位置规则下，旧位置不依赖新出现的未来 token，因此旧 K/V 可复用。新 Query 读取已有及新增的 K/V，得到当前输出；不缓存并不意味着算法定义不同，而是可能重算更多。

本次单层示例：B=1、KV heads=2、已缓存 N=5、每头宽4；K 与 V 各为 1×2×5×4，共80个数。新增一个 token 后各变成 1×2×6×4，共96个数。实际总缓存还乘层数及每数占用字节，并取决于精度与缓存实现。

## 易错边界

减少重复计算不等于没有内存增长。不同前缀、模型版本或位置规则的缓存不能随意混用；跨用户复用还涉及权限。KV Cache 不是记录“模型已经想过什么”的自然语言摘要。
