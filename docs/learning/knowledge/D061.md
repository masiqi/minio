# D061｜实现 Agent Loop 与显式状态机

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M06 · 前置：D058–D060

## 预习：问题与知识地图

Agent Loop 要将模型建议变成受控状态转换。任务状态、聊天消息和工具调用状态并不是同一份数据：消息记录“说了什么”，调用状态记录“某动作到了哪一步”，任务状态记录“目标完成到哪里”。

## 核心框架与案例

本次状态示意：RECEIVED → MODEL_PENDING → TOOL_PROPOSED → VALIDATED → AUTHORIZED → EXECUTING → OBSERVED → CONTINUE/DONE；同时允许 FAILED、CANCELLED、BUDGET_EXHAUSTED 等结束。状态名是教学设计，可按项目调整。

每次模型响应先区分答案、工具请求和非法响应。执行器负责确定性校验、授权与调用；工具结果回填后，模型可以建议下一步，但 runtime 仍强制预算和终止边界。不要把所有异常直接交给模型无限重试。

本次例：模型请求查询订单，工具超时。系统应保留错误与尝试信息，按策略有限恢复或终止；不能把不存在的成功结果写入后续上下文。

## 易错边界

while True 加一个模型调用不是可靠 Agent。模型最终说“完成”不保证环境状态满足目标。工具执行中用户取消时，应明确哪些动作已发生、哪些仍能停止。
