# D086｜ADR、Runbook、复现与交付清单

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M09 · 前置：D081–D085

## 预习：问题与知识地图

交付要让另一位工程师不依赖聊天历史也能运行、排错和理解取舍。README 告诉怎样开始，架构说明职责，ADR 记录为什么选择，Runbook 指导异常时怎样操作，测试/评测提供实际证据。

## 核心框架与案例

本次 ADR 骨架：问题与约束 → 备选方案 → 对照证据 → 决定 → 代价/风险 → 何时复议。原卡要求三份：检索策略、状态/副作用、框架/runtime，不是三篇产品介绍。

Runbook 则围绕症状：怎么发现、先检查哪些数据、怎样止损、何时回滚/升级人工、怎样验证恢复。比如“工具超时增多”需定位 provider/网络/队列/重试，而不是一句“重启服务”。

复现包包含依赖和模型/数据/索引版本、配置样例、授权说明、测试与评测命令、运行条件、成本边界及已知限制；不提交真实密钥或无授权资料。

## 易错边界

漂亮架构图不是运行证据。将计划写成完成会破坏交接。只记录成功步骤而不记录失败处理，会让新维护者在事故时仍依赖原作者。

## 复习：先独立回答

1. ADR 与 Runbook 的核心问题有什么不同？
2. 新环境跑出不同答案，交付包应该帮助核对哪些版本？

<details><summary>展开核对要点</summary>

ADR 解释选择与权衡，Runbook 指导运行异常的处理。应核对代码、依赖、模型、tokenizer、prompt、索引/数据、工具配置和随机/硬件条件。

</details>
