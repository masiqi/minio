# D070｜MCP 工具适配与生命周期实验

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M07 · 前置：D068、D069

## 预习：问题与知识地图

把已有工具包装为 MCP 能力，应改变通信适配，不应悄悄改变工具的权限、副作用和错误语义。链路：原契约 → SDK server 适配 → client 调用 → 结果/错误转换 → 取消、断连、重连与资源清理。

## 核心框架与案例

本次实验用 P2 的只读检索或 mock 工具。先验证发现和正常调用，再加入错误参数、连接中断、超时、取消与重连。每类错误应映射为 runtime 可以处理的类型，不能所有情况返回空文档列表。

取消是协议和执行生命周期的一部分，不是逆转所有已发生动作。即使 client 不再等待，server 仍可能正在执行，需要确认执行器的停止能力与清理策略；重连之后也不能盲目重放写请求。

版本不匹配时根据明确兼容策略降级或拒绝；不靠猜测补字段继续执行。

## 易错边界

一次 tool call 成功不能证明连接资源都回收。协议成功响应也可能包含业务无结果或错误，需按契约解释。适配层测试不能取代底层幂等与审批测试。

## 复习：先独立回答

1. 接上 MCP 后，原工具的哪些测试应继续复用？
2. Client 取消成功，为什么还要查看 server 资源与业务结果？

<details><summary>展开核对要点</summary>

类型/范围校验、权限、结果语义、副作用和幂等等业务契约测试。取消可能仅停止等待，远端动作与资源清理是否完成仍需证据。

</details>

## 动手与达标证据

用固定 SDK 版本实现一次只读调用，完成成功/错误/中断/取消/清理测试并记录时序；不使用真实生产秘密。
