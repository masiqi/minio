# D024｜T06B：泛化、数据划分与训练故障

[目录](README.md) · [原教学卡](../daily/D001-D030-foundations-training.md) · M02 · 前置：D015、D023

## 预习：问题与知识地图

训练损失衡量已经用于更新的样本；泛化关心没有被学习过程直接利用的数据。Train 用于拟合，validation 用于选择配置与诊断，test 用于在选定方案后作保留评估。边界不仅是文件夹，也包括重复内容和调参信息。

## 核心框架与例子

本次例子：同一本书切成很多重叠 chunk，再随机将 chunk 分到训练与测试，可能让同一内容出现在两边。看似未知问题，实际上模型或检索配置已经接触过近重复证据。应按任务的独立单位划分，例如文档、用户、时间或事件，再做去重与审查。

诊断顺序：先确认数据与目标正确 → 检查训练是否真的更新 → 看 train/validation 的走势 → 按任务类别找失败。训练变好而验证变差可能是过拟合，也可能涉及分布差异或评价错误，不能只凭两条数字直接定因。

## 易错边界

反复看测试集挑参数，会把测试集变成开发反馈。小训练集拟合成功是排错信号，不是产品能力证明。评价集被污染时，更多小数位不能让结论更可信。
