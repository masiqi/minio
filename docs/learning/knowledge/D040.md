# D040｜RoPE、MHA/MQA/GQA 与长上下文边界

## 预习：按两个子问题阅读

第一问：位置怎样影响 Q/K 的匹配？第二问：多少组 Query 共用多少组 K/V？两者分别影响位置关系与缓存/表达预算，不要因为同在长上下文模型里就当作同一种优化。

## 核心框架与例子

二维旋转 R(θ)=[[cosθ,-sinθ],[sinθ,cosθ]]。RoPE 对向量的成对维度施加位置相关旋转。以列向量约定，(R(mθ)q)ᵀ(R(nθ)k)=qᵀR((n-m)θ)k，位置差进入匹配；旋转方向/记号依实现约定，不是反求位置编号。

本次 head 示例：Query heads=8、每头宽4。MHA 有8组 K/V；MQA 有1组；GQA 可有2组，由 Query 组共享。B=1、N=10 时，K 缓存分别可记为 1×8×10×4、1×1×10×4、1×2×10×4，V 同理。共享的是 K/V 组，不是把输入 token 切走。

## 易错边界

RoPE 不是简单给 token embedding 加同维 PE；常见做法作用于 Q/K。GQA 不等于所有 Head 完全相同。公式能处理很大的位置、接口允许很长窗口，都不证明长距离证据能被可靠使用。

## 复习：先独立回答

2. 为什么需要把“支持的长度”和“在该长度的质量”分开报告？
