# D046｜文档解析、身份、版本、更新与删除

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M05 · 前置：[D045](D045.md)

## 预习：问题与知识地图

RAG 的证据需要知道“来自哪份文档、哪个版本、哪个位置”。只有一堆文本和向量，后续引用、撤权、更新和删除就很难可靠完成。数据链：原始对象 → 解析结构 → 稳定身份/版本/来源位置 → chunks → 派生索引与缓存。

## 核心框架与案例

本次 schema 示例：document_id、version、source_uri、source_span、tenant_id、access_policy、content_hash。它是教学设计，不要求所有系统字段名相同。Document ID 表示身份，version 表示某次内容状态；同名文件不保证是同一版本。

假设政策文档 v1 被 v2 替代：不仅原文本要变，相关 chunks、embedding、倒排、图关系与缓存都要按策略更新或失效。删除可能还涉及长期 Memory 和导出产物，要列出派生链，不能只删一个数据库表。

解析应保留标题层级、表格对应、图像证据与定位信息；纯文本转换可能丢失语义，不默认 OCR 或多模态解析总能无损。

## 易错边界

内容 hash 与稳定业务身份作用不同。引用页码存在不代表引用的版本正确。重新入库完成前可能有新旧混用窗口，应设计版本发布与回退。
