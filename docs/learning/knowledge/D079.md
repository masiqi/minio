# D079｜版本化评测、发布、在线监测与回滚

[目录](README.md) · [原教学卡](../daily/D061-D090-agent-production.md) · M08 · 前置：D076–D078

## 预习：问题与知识地图

AI 行为不仅取决于模型文件。Prompt、检索索引、工具、数据、配置、SDK 和模型版本都可能改变输出。发布链：版本化变更 → 离线回归 → 风险门槛 → 分阶段发布 → 在线观察/人工反馈 → 停止或回滚。

## 核心框架与案例

本次变更只调整 prompt，却让模型在无证据时更爱给确定答案。格式测试可能仍通过，引用/拒答评测却退步，因此发布需要多维门槛。若发现问题，只回滚应用代码而没恢复 prompt 或索引版本，可能不能恢复旧行为。

A/B 比较需要适当流量分配、风险控制与指标定义；教学项目可先用固定离线任务和模拟流量，不将模拟说成线上真实收益。点赞、使用率和任务质量不同，单一指标变好不证明因果改进。

## 易错边界

持续用同一保留集调参会污染评价。线上输入分布变化可能让原门槛不足，需要监测漂移与新失败。失败案例中的私有信息不应无条件回流训练或日志。

## 复习：先独立回答

1. 为什么只给模型权重打版本不够复现系统？
2. 发布后满意度提高，为什么还不能直接说新模型更准确？
