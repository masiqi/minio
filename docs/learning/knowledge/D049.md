# D049｜Sparse、Dense 与 Hybrid Retrieval

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M05 · 前置：[D048](D048.md)

## 预习：问题与知识地图

不同检索方法弥补不同失败。Sparse/BM25 关注词项与词频等统计，适合精确标识和词面匹配；dense 用向量表示语义改写；hybrid 合并候选或排名。不是越新的方法就越适合所有问题。

## 核心框架与案例

本次查询 A 是“ERR-4729 怎么处理”，查询 B 是“登录后一直被踢出来”。A 可能依赖精确错误码，B 可能需要语义改写匹配“会话失效”。用同一套文档测试 sparse、dense 和融合，先保存候选，再看生成答案。

BM25 分数与向量相似度通常不在同一尺度，不能未经校准直接按数值大小相加。可以使用明确定义的分数归一化或排名融合，但要记录规则和参数，并检查新增误召回。

## 易错边界

Hybrid 不保证总是更好；更多候选可能增加重复、延迟和排序噪声。只比较最终回答，可能把生成模型的随机变化误认成检索提升。某一类问题获益不等于整个数据域获益。

## 复习：先独立回答

1. 为什么含罕见编号的问题可能让词项检索占优？
2. 融合后答案提高，但同时换了模型和 prompt，能归因于融合吗？

<details><summary>展开核对要点</summary>

编号的准确出现可能比语义近似更重要；向量不一定保留精细词面差异。不能直接归因，变量同时变化导致无法分离作用，需同条件对照或消融。

</details>
