# D059｜Tool Contract、Schema 与错误协议

[目录](README.md) · [原教学卡](../daily/D031-D060-transformer-rag.md) · M06 · 前置：[D058](D058.md)

## 预习：问题与知识地图

模型是可能产生无效请求的调用方。Tool Contract 不只包括函数名，还包括用途、输入 schema、业务限制、权限要求、副作用、返回结构和可恢复错误。Schema 验证解决结构问题，不替代授权。

## 核心框架与案例

本次工具示意：search_documents(query, limit)。类型正确的 limit=1000000 仍可能违反业务预算；query 正确也可能请求当前用户无权读取的资料。校验应按类型、范围、主体与对象等层次执行，再调用实际后端。

结构化错误可区分 INVALID_ARGUMENT、NOT_AUTHORIZED、NOT_FOUND、UPSTREAM_UNAVAILABLE，并提供安全的可恢复提示。错误信息应帮助重新规划，但不能泄漏数据库凭证、内部敏感路径或别的租户数据。

只读和写操作的副作用不同，应明确标记。SQL 教学示例使用参数化查询与最小只读权限，不给模型开放任意 SQL 或系统命令执行。

## 易错边界

让模型“自己修参数”不意味着先执行非法请求。空结果、拒绝访问和上游失败不能都当成“没找到”。工具输出过大还会冲击 Context 与预算，必须有截断/分页/摘要契约。
