# 教学 Checkpoint：跨会话恢复协议

版本：1.0；建立日期：2026-10-09。默认仓库 masiqi/minio。

## 1. 三种文档各管什么

教学计划规定应该学什么；LEARNING_STATE 维护当前能力与复习索引；checkpoint 保存具体教学现场，包括例子、参数、实际输出、学生回答、已排除的问题和下一动作。它不同于保存模型权重/optimizer 状态的训练 checkpoint。

[LATEST.md](LATEST.md) 是唯一当前指针。每次新增 YYYY-MM-DD-NNN.md 快照，不把过去记录覆写成新的学习结果。本次是第一份正式教学 checkpoint；过去的日报保持原样，不追溯伪造曾经保存过的 checkpoint。

## 2. 开课恢复门槛

教练在当前回复实际读取：PLAN → LATEST → 指定完整快照 → LEARNING_STATE → 对应日卡。先从快照获得当前阶段和答案证据，再选题。代码搜索无结果不能证明已知路径不存在，应直接读取已知文件；不遍历其他仓库。

恢复后用一句话说明真实断点，例如“单步 SGD 已验证，接多轮 loop”；不要求用户再复述已保存答案。已答题不仅按数字去重，也按考查意图去重：把10000/100换成2000/20仍是同一类基本 epoch 题，不算新知识。

允许复习，但必须由具体待验证点、复习触发或新证据需要驱动，说明是在复测哪项能力。不能将教练忘记进度当成学生需要从头学。

文件缺失或内容冲突时，先读取同一提交下的关联文件核对；无法解决则说明缺哪条记录，仅询问最小缺口。最新用户明确报告的行为可补充较旧仓库状态，标为用户报告；不得因旧文件未记载就否认发生过，也不得把报告升级为已远程实测。

## 3. 每个快照必须保存的字段

| 字段 | 内容 |
| --- | --- |
| 元数据 | checkpoint ID、记录日期、前一 checkpoint（首次为无）、来源提交、触发原因；不编造精确时长 |
| 能力定位 | M/D 编号、已完成的子步骤、跨单元已接触项、未通过的前置；不是用单一进度百分比 |
| 实验现场 | 模型公式、输入/目标、参数、Loss 聚合、优化器/学习率、CPU/GPU、文件名（已知才写）、关键顺序 |
| 输出证据 | 用户原样贴出的输出，与教练推导/补写的结果分开；源代码是否真的读取过 |
| 已问已答 | 稳定问题 ID、考查内容、用户回答、正确/纠正/提示程度；需要时保留错误与后续修正 |
| 不重复项 | 不再开场重教的定义/原题/安装步骤，不是永久免于任何迁移或延迟验证 |
| 四维状态 | Concept/Mechanism/Engineering/Interview，各自证据；跟跑示例不等于从空白独立实现 |
| 未完事项 | 代码未做、边界未验、教师造成的混淆、后续章节及依赖 |
| 下一动作 | 恢复时具体从哪一行或哪项实验接，下一观察点是什么；不只写“继续学习” |
| 复习 | 项目触发或计划日期、验证目标和去重规则；没有结果不预写通过 |

## 4. 何时保存

在当前交互中，完成一个可验证的小里程碑、收到关键代码输出、发生重要纠错、准备转题/换设备、用户要求保存或结束时，执行一次适当粒度的保存。对同一小步骤的碎片语音不逐句提交；合并成一个带证据的里程碑。

流程：读 HEAD/现文件 → 汇总已发生的证据 → 新建快照 → 更新 LATEST 和当前状态 → 尽量同一个 commit 原子提交 → 回读新文件、检查指针与下一入口 → 才向用户报告已保存。PLAN/根 README 只指向动态入口，不每次复制旧的“下一步”文字。

保存是当轮实际工具操作，不是后台承诺。用户离线时不会凭本文件自动执行保存，也没有定时提醒被创建。写入失败时明确哪些未保存，必要时交付可复制文本；不得用“记住了”替代提交。

## 5. 一致性与历史

同一轮读取尽量固定提交 SHA。更新分支使用非强制且校验预期 HEAD；若分支已前进，读取并合并后再提交，不覆盖他人新内容。快照属于日期化历史；需纠错时新增带 supersedes/勘误说明的记录，而非静默改历史。

当前状态摘要与最新快照必须使用相同 checkpoint ID。保留旧日报和旧计划的不可变 Git 历史。过去教师误判/题干变化/错误命令单独标记，不写成学习者退步。课程日卡和90张知识框架继续有效，本协议不重新编排课程。

## 6. 恢复验收（仅检查记录，不测学生）

假设下一位教练只看到仓库，应能回答：最近一次实际运行是什么？参数和 Loss 是多少？用户最后答对什么？哪些题不能再问？环境是否已可用？哪些能力还没有证据？下一项具体动作是什么？若这些问题答不出，快照尚不足以交接。
